# 새 검증 케이스 추가 가이드

면접 답변 노트에서 "이거 실제로 그런가?" 싶은 문장을 발견했을 때의 절차다.

## 1. 명제를 한 문장으로 자른다

검증 가능한 문장이란 **관측 가능한 결과로 참/거짓이 갈리는 문장**이다.

| 나쁜 명제 | 좋은 명제 |
|---|---|
| "JPA 는 성능이 좋다" | "fetch join 을 쓰면 SQL 이 1+N 회에서 1회로 준다" |
| "인덱스를 잘 걸어야 한다" | "선택도 0.001% 조건에서는 옵티마이저가 인덱스를 선택한다" |
| "비동기가 빠르다" | "@Async 메서드는 호출자의 트랜잭션을 전파받지 않는다" |

명제를 자를 수 없다면, 그 답변은 아직 이해하지 못한 것이다.

## 2. 케이스를 만든다

```java
package io.webboy.verify.labs.<category>;

@Component
public class MyCase extends VerificationCase {

    @Override public String id()       { return "SPRING-07"; }   // 분류-일련번호
    @Override public String category() { return "spring"; }
    @Override public String question() { return "면접에서 받은 질문 원문"; }
    @Override public String claim()    { return "내 답변이 주장하는 명제"; }

    // JIT/GC/타이밍에 좌우되면 true
    @Override public boolean nondeterministic() { return false; }

    @Override
    protected void verify(Evidence evidence) throws Exception {
        // 1) 실행
        var observed = doSomething();

        // 2) 관측값 기록 — 리포트에 그대로 실린다
        evidence.fact("관측한 값", observed);

        // 3) 명제 검증
        evidence.expect("명제가 성립한다", observed == expected);
        evidence.expectEquals("값이 일치한다", expected, observed);
        evidence.expectFlaky("환경에 따라 달라질 수 있는 명제", timing < threshold);

        // 4) 면접에서 덧붙일 맥락
        evidence.note("이 동작은 ~한 이유로 그렇고, 실무에서는 ~를 주의한다.");
    }
}
```

## 3. 세 가지 기록 방식을 구분한다

- `fact` — **판정과 무관한 관측값**. 시간, 카운트, 클래스 이름, 실행계획 텍스트 등.
- `expect` — **깨지면 답변이 틀린 것**. 여기 넣은 게 실제 주장이다.
- `expectFlaky` — **깨져도 답변이 틀렸다고 볼 수 없는 것**. 성능 비교, GC 타이밍, 옵티마이저 선택.

`expect` 를 남발하면 테스트가 자주 깨져 신뢰를 잃고,
`expectFlaky` 를 남발하면 아무것도 검증하지 않는 문서가 된다. 이 경계가 이 랩의 핵심이다.

## 4. 체크리스트

- [ ] `id` 가 기존 케이스와 겹치지 않는가 (겹치면 기동 시 `IllegalStateException`)
- [ ] 케이스가 **자기 자신을 정리**하는가 (임시 테이블 DROP, 캐시 clear, 스레드 풀 shutdown)
- [ ] 여러 번 연속 실행해도 같은 결과가 나오는가 (랜덤 키·UUID 로 격리했는가)
- [ ] 스레드를 만들었다면 데몬이고, 타임아웃 상한이 있는가 (영원히 매달리는 케이스 금지)
- [ ] `note` 에 "면접에서 덧붙일 한 줄"이 들어 있는가
- [ ] `docs/01-검증-케이스-목록.md` 에 질문 원문(한/일)을 추가했는가

## 5. 실행

```bash
./gradlew :verify-labs:test --tests '*VerificationSuiteTest*'
cat verify-labs/build/reports/verification.md
```

또는 개별 실행:

```bash
./gradlew :verify-labs:bootRun
curl -X POST localhost:8080/verify/run/SPRING-07 | jq
```
