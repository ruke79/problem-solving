# 면접 용어 정의 — Java · Spring

[`java-면접/`](java-면접/README.md)(Q1~Q145) 과 [`spring-면접/`](spring-면접/README.md)(Q1~Q145) 의
**290문항에 실제로 나오는 용어**만 모아 정의한 사전이다. 문항 제목을 전수로 훑어 뽑았고,
거기에 없는 용어는 넣지 않았다.

## 어떻게 쓰나

- **답변을 만들기 전에** 이 표에서 용어의 경계를 확인한다. 면접에서 가장 흔한 실수는 모르는 것이
  아니라 **비슷한 두 개를 섞는 것**이다(가시성 vs 원자성, 인증 vs 인가, 낙관 락 vs 비관 락).
- **日本語 열은 면접에서 실제로 말하는 형태**다. 한국식 한자어를 그대로 읽으면 통하지 않는 것이
  많다 — 지연 로딩은 `遅延ローディング`, 멱등성은 `冪等性(べきとうせい)`, 기아는 `スターベーション` 쪽이 자연스럽다.
- **근거** 열의 `SPRING-01` 같은 표시는 이 저장소에서 **실행으로 확인한 케이스**다
  (`./gradlew test -Dverify.only=SPRING-01`). 표시가 없는 항목은 **문서·책 기반 정의**이고,
  면접에서 수치를 인용할 때는 그 차이를 밝히는 편이 안전하다([`java-면접/README.md`](java-면접/README.md) 참고).

> **이 문서는 정의만 담는다.** "어떻게 답하는가"는 각 세트의 Part 파일과 `필수-키노트.md` 에 있다.
> 정의가 길어질 만한 것은 문항 번호를 달아 뒀으니 그쪽을 보면 된다.

# 1부 — Java

| `default` 메서드 | defaultメソッド | 인터페이스에 구현을 넣어 **기존 구현체를 깨지 않고** 메서드를 추가하기 위한 장치(Java 8). `Collection.stream()` 이 그 예다. | Q13 |
| 접근 제어자 | アクセス修飾子 | `private`(클래스 안) · package-private(같은 패키지) · `protected`(패키지 + 하위 클래스) · `public`. 기본값은 package-private. | Q14 |

| 체크 예외 / 언체크 예외 | チェック例外 / 非チェック例外 | 체크 예외는 컴파일러가 처리를 강제한다(복구 가능한 상황), 언체크(`RuntimeException`)는 강제하지 않는다(프로그래밍 오류). | Q18 |
| try-with-resources | try-with-resources | `AutoCloseable` 자원을 블록 종료 시 역순으로 닫는다. finally 로 닫을 때 생기는 **자원 누수와 예외 가림**을 없앤다(억제된 예외로 보존). | Q19 |
| 제네릭 | ジェネリクス | 타입을 매개변수로 받아 컴파일 타임에 타입 안전성을 확보하고 캐스팅을 없앤다. | Q21 |
| 타입 소거 | 型消去 | 제네릭 타입 정보가 컴파일 후 사라지는 것. 그래서 `new T[]`·`instanceof List<String>`·오버로딩 구분이 안 된다. | Q22 |
| 상한/하한 와일드카드 (PECS) | 上限/下限ワイルドカード | `? extends T` 는 읽기(생산자), `? super T` 는 쓰기(소비자). "Producer Extends, Consumer Super". | Q23 |
| `enum` | enum | 인스턴스가 고정된 타입. 싱글턴 보장·`switch` 사용·상태와 동작을 함께 넣을 수 있어 상수 나열보다 안전하다. | Q24·Q138 |
| `record` | record | 불변 데이터 운반용 타입. 생성자·접근자·`equals`·`hashCode`·`toString` 을 자동 생성한다. **가변 객체를 담으면 불변이 아니다.** | Q25 · `JVM-05` |
| `var` | var | 지역 변수 타입 추론. 우변에서 타입이 명백할 때만 쓰고, 반환 타입이 모호한 경우에는 피한다. 필드·파라미터에는 못 쓴다. | Q26 |
| 클래스 초기화 순서 | クラスの初期化順序 | static 필드·static 블록(최초 1회) → 인스턴스 필드·초기화 블록 → 생성자. 상위 클래스가 먼저다. | Q27 |
| 패턴 매칭 | パターンマッチング | `instanceof` 검사와 캐스팅·바인딩을 한 번에 하는 문법(Java 16+). `switch` 패턴으로 확장됐다. | Q28 |
| 가변 인자 | 可変長引数(varargs) | `T...` 는 내부적으로 배열이다. 오버로딩 모호성과 제네릭 배열 경고(`@SafeVarargs`)에 주의. | Q29 |
| 내부 클래스 / 정적 중첩 클래스 | 内部クラス / staticネストクラス | 내부(비static) 클래스는 바깥 인스턴스 참조를 갖는다 → **누수 원인**. 바깥을 안 쓰면 `static` 으로 선언한다. | Q30·Q96 |

## 2. 컬렉션

| 용어 | 日本語 | 정의 | 문항 · 근거 |
|---|---|---|---|
| List / Set / Map | List / Set / Map | 순서 있는 중복 허용 / 중복 불허 / 키-값. 선택 기준은 "중복을 허용하는가, 키로 찾는가, 순서가 필요한가". | Q31 |
| `ArrayList` / `LinkedList` | ArrayList / LinkedList | 배열 기반(임의 접근 O(1), 중간 삽입 시 복사) vs 연결 리스트(삽입 O(1)이지만 **탐색이 O(n)**). 실무는 대부분 `ArrayList`. | Q32 |
| 용량과 증가 | 容量(capacity)と拡張 | `ArrayList` 는 가득 차면 약 1.5배로 새 배열을 만들어 복사한다. 크기를 알면 초기 용량을 주어 복사를 없앤다. | Q33 |
| 버킷 / 해시 충돌 | バケット / ハッシュ衝突 | 해시값으로 정한 저장 칸이 버킷. 다른 키가 같은 버킷에 오는 것이 충돌이고, 연결 리스트로 잇는다. | Q34·Q36 |
| 트리화 | ツリー化(treeify) | 한 버킷의 충돌이 8개를 넘고 테이블이 64 이상이면 연결 리스트를 **레드-블랙 트리**로 바꿔 최악 O(n) → O(log n). | Q36 |
| 로드 팩터 / 리사이즈 | 負荷率 / リサイズ | 기본 0.75. 요소 수가 `용량 × 0.75` 를 넘으면 용량을 2배로 늘리고 전 요소를 재배치한다(비용이 크다). | Q37 |
| 가변 키 문제 | 可変キー問題 | `HashMap` 키의 필드를 넣은 뒤 바꾸면 해시가 달라져 **그 값을 영영 못 찾는다.** 키는 불변이어야 한다. | Q38 |
| `ConcurrentHashMap` | ConcurrentHashMap | 버킷 단위 락·CAS 로 동시 접근을 허용하는 맵. **개별 연산만 원자적**이라 "get 후 put" 은 안전하지 않고 `compute`·`merge` 를 써야 한다. | Q39·Q40 · `CON-01` |
| `LinkedHashMap` | LinkedHashMap | 삽입(또는 접근) 순서를 유지하는 맵. `removeEldestEntry` 로 **LRU 캐시**를 만들 수 있다. | Q41·Q53 |
| `TreeMap` | TreeMap | 정렬된 맵. `Comparable`/`Comparator` 기준으로 범위 조회(`headMap`·`tailMap`)가 된다. 조회는 O(log n). | Q42 |
| `Comparable` / `Comparator` | Comparable / Comparator | 타입 자신이 정의하는 자연 순서 vs 외부에서 주는 비교 규칙. 정렬 기준이 여러 개면 `Comparator`. | Q43 |
| `compareTo` ↔ `equals` 정합성 | 整合性 | `compareTo == 0` 과 `equals == true` 가 어긋나면 `TreeSet`·`TreeMap` 이 "중복 아님"을 다르게 판단해 원소가 사라진다. | Q44 |
| fail-fast / `ConcurrentModificationException` | フェイルファスト | 순회 중 컬렉션 구조가 바뀌면 `modCount` 불일치로 즉시 예외. `Iterator.remove()` 나 `removeIf` 를 쓴다. | Q45 |
| 고정 크기 뷰 / 불변 컬렉션 | 固定長ビュー / 不変コレクション | `Arrays.asList` 는 배열의 **뷰**라 `add` 불가·`set` 은 원본에 반영. `List.of` 는 진짜 불변, `unmodifiableList` 는 원본이 바뀌면 같이 바뀌는 래퍼. | Q46·Q47 |
| `BlockingQueue` | BlockingQueue | 비면 대기·차면 대기하는 큐. 생산자-소비자와 **유계 큐로 배압을 만드는** 데 쓴다. | Q50·Q73 |
| `Collections.synchronizedList` | 同期化ラッパー | 메서드마다 락을 걸 뿐이라 **복합 연산과 순회는 여전히 직접 동기화**해야 한다. | Q51 |
| `CopyOnWriteArrayList` | CopyOnWriteArrayList | 쓰기 때마다 배열을 복사한다. 읽기 압도적 우위(리스너 목록 등)에서만 유효하고, 쓰기가 잦으면 최악이다. | Q52 |

## 3. 동시성

| 용어 | 日本語 | 정의 | 문항 · 근거 |
|---|---|---|---|
| 프로세스 / 스레드 | プロセス / スレッド | 프로세스는 독립된 메모리 공간, 스레드는 그 안에서 힙을 공유하고 스택만 따로 갖는 실행 흐름. | Q56 |
| `Runnable` / `Callable` | Runnable / Callable | 반환값·체크 예외가 없는 쪽과 있는 쪽. `Callable` 은 `Future` 로 결과와 예외를 받는다. | Q57 |
| `synchronized` / 모니터 | synchronized / モニター | 객체마다 있는 잠금. **상호 배제와 가시성(진입 시 무효화, 해제 시 반영)** 을 함께 보장한다. 재진입 가능. | Q59 |
| `volatile` | volatile | **가시성과 재정렬 금지**만 보장하고 원자성은 보장하지 않는다. `i++` 는 여전히 안전하지 않다. | Q60·Q61 · `CON-03` |
| 가시성 / 원자성 / 순서 | 可視性 / 原子性 / 順序性 | 한 스레드의 쓰기가 다른 스레드에 보이는가 / 연산이 쪼개지지 않는가 / 실행 순서가 보장되는가. 셋은 서로 다른 문제다. | Q59·Q60 |
| happens-before | happens-before | "A 의 결과가 B 에게 반드시 보인다"는 JMM 의 순서 규칙. 락 해제→획득, volatile 쓰기→읽기, `Thread.start`·`join` 등이 만든다. | Q62 |
| CAS | CAS(コンペア・アンド・スワップ) | "기대값과 같으면 새 값으로 바꾼다"는 CPU 원자 명령. 락 없이 갱신하고 실패하면 재시도(스핀)한다. | Q63 |
| `LongAdder` | LongAdder | 셀을 여러 개 두어 경합을 분산하고 읽을 때 합산한다. **쓰기 경합이 심한 카운터**에서 `AtomicLong` 보다 낫다. | Q64 · `CON-02` |
| `ReentrantLock` | ReentrantLock | 명시적 락. 타임아웃(`tryLock`)·인터럽트(`lockInterruptibly`)·공정성·다중 `Condition` 이 필요할 때 `synchronized` 대신 쓴다. | Q65 · `CON-05` |
| `ReadWriteLock` | ReadWriteLock | 읽기끼리는 공유, 쓰기는 배타. **읽기가 압도적으로 많을 때만** 이득이고 아니면 오버헤드다. | Q66 |
| `ThreadLocal` | ThreadLocal | 스레드마다 별도 값. **스레드 풀에서 스레드가 재사용되므로 `remove()` 하지 않으면 다음 작업에 값이 남는다**(누수·정보 유출). | Q67 · `CON-04` |
| `wait`/`notify` vs `sleep` | wait/notify と sleep | `wait` 는 **락을 놓고** 대기하고 `notify` 로 깨어난다. `sleep` 은 락을 쥔 채 잔다. | Q68 |
| 가짜 깨어남 | 偽の目覚め(spurious wakeup) | 통지 없이 `wait` 가 깨어날 수 있어, 조건 검사는 `if` 가 아니라 **`while`** 로 감싼다. | Q69 |
| 우아한 종료 | グレースフルシャットダウン | `shutdown()` → `awaitTermination()` → 안 끝나면 `shutdownNow()` → 다시 대기, 그리고 인터럽트 상태 복원. | Q70 |
| 스레드 풀 크기 | スレッドプールのサイズ | CPU 바운드는 코어 수 ±1, I/O 바운드는 `코어 수 × (1 + 대기/서비스)`. **먼저 재고 나서 정한다.** | Q71·Q76 |

| 거부 정책 | 拒否ポリシー | 큐가 차면 `AbortPolicy`(예외)·`CallerRunsPolicy`(호출 스레드가 실행 → 자연스러운 배압)·`Discard*` 중 고른다. | Q73 |
| `CompletableFuture` | CompletableFuture | 논블로킹 조합(`thenApply`·`thenCompose`·`allOf`)과 예외 처리(`exceptionally`)를 제공. `Future.get()` 의 블로킹을 없앤다. | Q74 |

## 정직한 고지

- **정의는 문서·책 기반이다.** `근거` 열에 케이스 id 가 있는 것만 이 저장소에서 **실행으로 확인**했다.
  나머지는 스펙·공식 문서·이 저장소의 요약([`notes/`](../notes/optimizing-java-2nd/README.md))을 근거로 적었다.
- **버전에 매인 서술이 있다.** 가상 스레드의 고정(JDK 21 → 24 해소)·ZGC 세대형(24 부터만)처럼
  판이 바뀐 것은 `notes/JVM-용어-변천사.md` 에 연표로 정리해 뒀다 — 면접에서 "지금은" 을 붙여야 하는 항목들이다.
- **일본어 표기는 실무에서 쓰는 형태를 골랐지만 원어민 검수를 받은 것은 아니다.**
  `docs/12-일본어-동사-전수-조사.md` 의 고지가 여기에도 그대로 적용된다.
- **여기 없는 용어는 문항에도 없다.** 두 세트의 문항 제목 290개를 전수로 훑어 뽑았고, 개수를 채우려고
  넣은 항목은 없다. 반대로 **문항에 있는데 표에 빠진 것을 발견하면 그것은 이 문서의 구멍**이다.
