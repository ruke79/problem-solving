# JavaScript 면접 — 필수 문항 지정과 키노트

> **시간이 부족할 때 이 파일만 보면 된다.** 50문항을 세 등급으로 나누고,
> S급에는 **일본어 한 문장**을 붙였다. 그 문장만 외워도 답이 성립한다.
>
> 등급 기준은 **출제 빈도 × 변별력**이다. 자주 나오는데 남들도 다 아는 것보다,
> **자주 나오는데 절반은 틀리는 것**을 위로 올렸다.
>
> ⚠️ **이 세트에는 실행 근거가 없다.** 이 저장소의 검증 모듈은 전부 JVM 기반이다([`README.md`](README.md)).
> 다만 **보안 세 문항(Q25 XSS · Q30 CORS · Q31 CSRF)은 서버 쪽 대응 케이스**가 있어
> (`SEC-01`·`SEC-02`·`SEC-03`), "프런트에서는 이렇게, 서버에서는 이렇게" 로 이어 말할 수 있다.

## 1. S급 — 반드시 나온다 (10문항)

### ① 이벤트 루프와 비동기 — 자바스크립트 면접의 핵심

**Q6. 이벤트 루프는 어떻게 동작하나** ★가장 자주
> コールスタックが空になると、まずマイクロタスクキューを**空になるまで**処理し、その後マクロタスクを一つ取ります。Promise のコールバックはマイクロタスク、`setTimeout` はマクロタスクなので、`setTimeout(fn, 0)` より Promise の方が先に走ります。

**Q7. Promise 의 상태와 `then` 체인** ★가장 자주
> pending から fulfilled か rejected へ一度だけ遷移します。`then` は新しい Promise を返すので連鎖でき、**`then` の中で Promise を返すとそれが解決されてから次に進みます**。`return` を書き忘れると待たずに進んでしまいます。

**Q10. 여러 비동기를 병행으로 돌릴 때** ★실무
> `for` の中で `await` すると直列になるので、並行にしたいなら Promise を先に作って `Promise.all` に渡します。ただし無制限に並行にすると相手のサーバやコネクション上限を壊すので、同時実行数を制限します。

**Q9. `async`/`await` 의 에러 처리** ★함정
> `try`/`catch` で囲みます。注意点は、**`await` を付け忘れた Promise は catch されない**ことで、それが未処理の rejection になります。Node なら `unhandledRejection` を監視します。

---

### ② 언어의 기초 — 여기서 대충 답하면 갈린다

**Q4. `this` 는 무엇으로 정해지나** ★가장 자주
> 呼び出し方で決まります。メソッド呼び出しならレシーバ、`new` ならその新しいインスタンス、`call`/`bind` なら指定したものです。**アロー関数だけが例外で、自分の `this` を持たず定義時の外側を使います**。

**Q3. 클로저란**
> 関数が定義されたときのスコープを覚えたまま持ち歩く仕組みです。プライベート変数やモジュールパターンに使いますが、DOM や大きなオブジェクトを掴んだままにすると解放されずメモリリークになります。

**Q1. `var`·`let`·`const` 의 차이**
> `var` は関数スコープで巻き上げられ、宣言前でも `undefined` として参照できてしまいます。`let` と `const` はブロックスコープで、宣言前の参照は TDZ でエラーになります。**`const` は再代入を禁止するだけで中身の変更は防ぎません**。

---

### ③ 메모리와 보안 — 실무에서 갈린다

**Q19. 메모리 누수는 언제 생기나** ★실무
> 一番多いのはイベントリスナーやタイマーの解除漏れです。DOM を消してもリスナーが参照を持っていると回収されません。調査は DevTools のヒープスナップショットを二点取って差分を見ます。

**Q24. 토큰을 `localStorage` 에 두면 안 되는 이유** ★보안 · 변별력
> **認証トークンを `localStorage` に置くと XSS で盗まれます。**セッションの識別子は `HttpOnly`・`Secure`・`SameSite` を付けた Cookie に置くのが基本で、ストレージには機密でない表示設定などを入れます。

**Q25. XSS 는 어떻게 막나** ★보안
> 出力時のエスケープが基本で、フレームワークが既定でやってくれるものを安易に外さないことです。多層で守るため、CSP でインラインスクリプトを制限し、Cookie は `HttpOnly` にして盗まれても使えないようにします。

## 2. A급 — 자주 나온다 (15문항)

| Q | 한 줄 |
|---|---|
| Q2 | `==` 는 형 변환 후 비교 → 원칙 `===`. 예외는 `== null` 관용구뿐 |
| Q5 | `class` 는 프로토타입의 문법 설탕 — 속은 프로토타입 체인 |
| Q8 | `all` 은 하나만 실패해도 전체 reject, `allSettled` 는 전부 돌려준다 |
| Q11 | 스프레드는 얕은 복사. 깊은 복사는 `structuredClone`(JSON 왕복은 `Date`·`undefined` 에서 깨짐) |
| Q12 | `??` 는 `0`·빈 문자열을 살린다 — `\|\|` 를 쓰면 `0` 이 사라지는 버그 |
| Q13 | 변환은 `map`, 걸러내기는 `filter`, `forEach` 는 중간에 못 빠져나온다 |
| Q14 | `sort`·`splice`·`reverse` 는 **원본을 바꾼다**. `sort` 기본은 문자열 비교 |
| Q15 | 사전으로 쓸 거면 `Map` — 객체는 `__proto__` 같은 키에서 사고 |
| Q16 | ESM 은 정적 분석 → 트리 셰이킹·톱레벨 `await` |
| Q17 | 제너레이터·비동기 이터레이터로 스트림을 다룬다 |
| Q18 | 디바운스는 "마지막 뒤 한 번", 스로틀은 "일정 간격 최대 한 번" |
| Q20 | `0.1+0.2` 문제 — 64비트 정수 ID 는 **문자열로 받는다** |
| Q21 | 타입스크립트는 컴파일 후 사라진다 → **경계에서 스키마 검증**이 따로 필요 |
| Q22 | `any` 는 검사 포기, `unknown` 은 좁히기를 강제 → 입력 수신부는 `unknown` |
| Q23 | 이벤트 위임 — 부모에 하나만 달고 `event.target` 으로 판정 |

## 4. 면접 30분 전 최종 점검 — 이것만은

**다섯 개의 "아니오"** 를 기억하면 함정 질문은 대부분 막힙니다.

| 질문의 유혹 | 정답 |
|---|---|
| `setTimeout(fn, 0)` 이 Promise 보다 먼저인가? | **아니오** — 마이크로태스크가 먼저 (Q6) |
| 화살표 함수도 `this` 를 가지나? | **아니오** — 정의 시점의 바깥을 쓴다 (Q4) |
| `const` 면 객체 내용도 못 바꾸나? | **아니오** — 재대입만 금지 (Q1) |
| 토큰을 `localStorage` 에 둬도 되나? | **아니오** — XSS 로 탈취된다 (Q24) |
| 타입스크립트를 쓰면 런타임에도 안전한가? | **아니오** — 타입은 컴파일 후 사라진다 (Q21) |

**그리고 하나의 "예"** — *`fetch` 에는 `AbortSignal.timeout` 으로 반드시 타임아웃을 준다.* (Q35)
