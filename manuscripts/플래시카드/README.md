## 카드의 구조

```
앞면   Q35. 同じクラス内のメソッドを呼ぶと @Transactional が効かないのはなぜですか？
뒷면   프록시를 거치지 않기 때문입니다 … (일본어 한 문장)
       — 같은 클래스 안에서 부르면 @Transactional 이 안 걸리는 이유
       실행 근거: SPRING-01
태그   spring Q35 빈출 SPRING-01
```

- **앞면은 면접에서 실제로 듣는 일본어 질문**이다(Part 파일의 문항 제목 그대로).
- **뒷면 첫 줄이 그 자리에서 말할 일본어 한 문장**이고, 그 아래에 한국어 뜻과 실행 근거를 붙였다.
- **태그로 걸러서 돌릴 수 있다** — `빈출`(28장) · `함정`(18장) · `실무`(17장) · `변별력`(11장) · `보안`(4장),
  그리고 `DB-14` 처럼 **이 저장소에서 실행으로 확인한 케이스 id**.

## 쓰는 법

**Anki 로 가져오기** — 탭 구분(TSV)이라 그대로 들어간다.

1. Anki → 파일 → 가져오기 → `전체.tsv` 선택
2. 필드 구분자 **탭**, 필드 매핑은 `앞면 / 뒷면 / 태그`
3. **"HTML 허용"을 켠다** — 뒷면의 줄바꿈이 `<br>` 이라 켜지 않으면 태그가 그대로 보인다
4. `#` 로 시작하는 앞의 두 줄은 주석이라 무시된다

**터미널에서 한 장씩 보기** — 도구 없이 확인만 할 때.

```bash
shuf -n 1 manuscripts/플래시카드/전체.tsv | awk -F'\t' '{print $1"\n\n"$2}' | sed 's|<br>|\n|g'
```

**태그로 골라 돌리기** — 예를 들어 함정 문항만.

```bash
grep -P '\t[^\t]*함정' manuscripts/플래시카드/전체.tsv | wc -l   # 18장
```

## 이 파일들은 생성물이다 — 직접 고치지 말 것

[`scripts/make-flashcards.py`](../../scripts/make-flashcards.py) 가 **키노트에서 뽑아 만든다.**

```bash
./scripts/make-flashcards.py           # 다시 만든다
./scripts/make-flashcards.py --check   # 키노트와 어긋나지 않았는지 검사 (CI 가 돌린다)
```

**손으로 옮겨 적지 않는 이유**는 하나다 — 카드는 키노트의 파생물이라, 손으로 베끼면 키노트를 고쳤을 때
조용히 어긋나고 **어긋난 쪽을 외우게 된다.** 그래서 키노트를 유일한 출처로 두고,
CI 의 `docs` 잡이 `--check` 로 어긋남을 실패로 잡는다([`docs/11`](../../docs/11-CI-CD-와-EC2-프리티어.md) §1-2).

카드 내용을 고치고 싶으면 **해당 세트의 `필수-키노트.md` 를 고친 뒤 다시 생성**한다.

## 정직한 고지

- **실행 근거가 붙은 카드는 26장뿐이다**(`DB-*`·`KAFKA-*`·`MSA-*`·`CN-*`·`JVM-*` 태그).
  나머지는 문서·책 기반이다. 면접에서 수치를 인용할 때는
  **"제 환경에서 재 봤을 때는"** 과 **"일반적으로 알려진 바로는"** 을 섞지 않는 편이 안전하다.
- **일본어는 원어민 검수를 받지 않았다.** `docs/12-일본어-동사-전수-조사.md` 의 고지가 그대로 적용된다.
- **S급만 담았다.** A급·B급은 카드로 만들지 않았다 — 86장을 넘기면 "매일 돌리는" 것이 어려워지고,
  그러면 카드의 목적 자체가 사라지기 때문이다. A급 이하는 각 키노트의 표로 훑는다.
