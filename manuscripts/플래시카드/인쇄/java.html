equals() をオーバーライドするとき hashCode() も一緒に実装する理由は？
equals 를 오버라이드할 때 hashCode 도 함께 구현하는 이유
JAVA Q2빈출
等しいオブジェクトは同じハッシュコードを返す、という契約があるからです。破ると HashMap が壊れ、put した値を get で取り出せなくなります。
JAVA Q8함정
Integer を == で比較すると値によって結果が変わるのはなぜですか？
Integer 를 == 로 비교하면 값에 따라 결과가 달라지는 이유
JAVA Q8함정
-128 から 127 まではキャッシュされたインスタンスが再利用されるので == でも true になりますが、それを超えると別インスタンスになり false になります。だからラッパー型は必ず equals() で比べます。

JAVA Q38함정
HashMap のキーに可変オブジェクトを使うとどうなりますか？
HashMap 의 키로 가변 객체를 쓰면 어떻게 되나
JAVA Q38함정
put 後にキーを変更すると hashCode が変わり、そのエントリを二度と取り出せなくなります。だからキーには不変オブジェクトを使うのが原則です。
JAVA Q40함정
ConcurrentHashMap を使っていれば get してから put する処理も安全ですか？
ConcurrentHashMap 을 쓰면 get 후 put 하는 처리도 안전한가
JAVA Q40함정
いいえ。個々のメソッドはアトミックですが、get して判断して put する組み合わせはアトミックではありません。compute や putIfAbsent のような複合操作用メソッドを使います。
JAVA Q60빈출
volatile と synchronized の違いは？
volatile 과 synchronized 의 차이
JAVA Q60빈출
volatile は可視性と並べ替え防止だけを保証し、相互排他はしません。だから count++ のような読み書き複合の操作は守れません。volatile が正しいのは、フラグのように単純な代入と読み取りだけの場合です。
JAVA Q67함정실무
ThreadLocal は何のためにあり、何に注意しますか？
ThreadLocal 은 무엇을 위한 것이고 무엇을 주의하나
JAVA Q67함정실무
スレッドが使い回されるので、remove() を呼ばないと前のリクエストの値が次のリクエストに漏れます。情報漏洩にもメモリリークにもなるので、finally で必ず remove() します。
JAVA Q71
スレッドプールのサイズはどう決めますか？
스레드풀 크기는 어떻게 정하나
JAVA Q71
CPUバウンドならコア数程度、I/Oバウンドなら「コア数 × (1 + 待ち時間 / 処理時間)」が目安です。ただしDBを使う処理ではコネクションプールが上限になるので、そちらと揃えないと意味がありません。
JAVA Q72변별력
Executors.newFixedThreadPool() を本番で使わない方がよい理由は？
newFixedThreadPool 을 프로덕션에서 쓰지 않는 편이 좋은 이유
JAVA Q72변별력
内部のキューが容量無制限だからです。処理が追いつかないとタスクが際限なく溜まり、最終的に OutOfMemoryError になります。本番では ThreadPoolExecutor を直接組み立て、キュー容量と拒否ポリシーを明示します。
JAVA Q75빈출
デッドロックはなぜ起き、どう防ぎますか？
데드락은 왜 일어나고 어떻게 막나
JAVA Q75빈출
複数のロックを異なる順序で取りに行き、互いに相手の解放を待つと起きます。一番実効性がある対策はロックの取得順序を全体で統一することで、これだけで循環待ちが消えます。
JAVA Q90
Minor GC と Full GC の違いは？
Minor GC 와 Full GC 의 차이
JAVA Q90
Minor GC は Young 領域だけなので短時間で終わり、Full GC は Old まで含むので停止時間が長くなります。だから運用で見るべきはFull GCの頻度と時間です。
