# Java 면접 — 필수 문항 지정과 키노트

> **시간이 부족할 때 이 파일만 보면 된다.** 145문항을 세 등급으로 나누고,
> S급에는 **일본어 한 문장**을 붙였다. 그 문장만 외워도 답이 성립한다.
>
> 등급 기준은 **출제 빈도 × 변별력**이다. 자주 나오는데 남들도 다 아는 것보다,
> **자주 나오는데 절반은 틀리는 것**을 위로 올렸다.

## 1. S급 — 반드시 나온다 (18문항)

### ① 동일성 · 불변

**Q2. `equals` 를 오버라이드하면 `hashCode` 도 해야 하는 이유** ★가장 자주
> 等しいオブジェクトは同じハッシュコードを返す、という契約があるからです。破ると `HashMap` が壊れ、`put` した値を `get` で取り出せなくなります。

**Q8. `Integer` 를 `==` 로 비교하면 값에 따라 결과가 달라지는 이유** ★함정
> `-128` から `127` まではキャッシュされたインスタンスが再利用されるので `==` でも `true` になりますが、それを超えると別インスタンスになり `false` になります。だからラッパー型は必ず `equals()` で比べます。

**Q3. `String` 이 불변인 이유**
> 理由は三つあります。文字列プールで安全に共有できること、ハッシュコードをキャッシュできるので `HashMap` のキーとして速いこと、そしてスレッドセーフになることです。

**Q16. 불변 클래스를 만드는 법**
> クラスを `final` にし、フィールドを `private final` にし、setter を作りません。見落としやすいのは**可変オブジェクトの防御的コピー**で、受け取るときと返すときの両方でコピーする必要があります。

---

### ② 예외 · 컬렉션

**Q18. 체크 예외와 언체크 예외의 구분 기준**
> 基準は**呼び出し側が回復できるか**です。代替手段を取れるならチェック例外、引数が不正などプログラムのバグならランタイム例外にします。

**Q20. `finally` 안에서 `return` 하면** ★함정
> `try` 側の `return` や例外を上書きしてしまいます。例外が投げられていても握りつぶされて原因が消えるので、`finally` の中では `return` も `throw` も書かないのが原則です。

**Q35. `HashMap` 의 `put` 흐름** ★가장 자주
> キーの `hashCode()` に補助ハッシュをかけてインデックスを決め、バケットが空なら新規ノード、既にあれば `equals()` で同じキーを探して上書きか末尾追加です。閾値を超えるとリサイズします。

**Q36. 해시 충돌이 나면**
> 同じバケットに連結リストとして繋がります。Java 8 からは、ノードが8個を超え配列長が64以上ならレッドブラックツリーに変換され、最悪ケースが O(log n) に抑えられます。

**Q38. `HashMap` 키에 가변 객체를 쓰면** ★함정
> `put` 後にキーを変更すると `hashCode` が変わり、そのエントリを二度と取り出せなくなります。だからキーには不変オブジェクトを使うのが原則です。

**Q40. `ConcurrentHashMap` 이면 `get` 후 `put` 도 안전한가** ★함정
> いいえ。個々のメソッドはアトミックですが、`get` して判断して `put` する**組み合わせはアトミックではありません**。`compute` や `putIfAbsent` のような複合操作用メソッドを使います。

---

### ③ 동시성

**Q60. `volatile` 과 `synchronized` 의 차이** ★가장 자주
> `volatile` は**可視性と並べ替え防止だけ**を保証し、相互排他はしません。だから `count++` のような読み書き複合の操作は守れません。`volatile` が正しいのは、フラグのように単純な代入と読み取りだけの場合です。

**Q67. `ThreadLocal` 과 스레드풀** ★실무 함정
> スレッドが使い回されるので、`remove()` を呼ばないと**前のリクエストの値が次のリクエストに漏れます**。情報漏洩にもメモリリークにもなるので、`finally` で必ず `remove()` します。

**Q71. 스레드풀 크기 산정**
> CPUバウンドならコア数程度、I/Oバウンドなら「コア数 × (1 + 待ち時間 / 処理時間)」が目安です。ただし**DBを使う処理ではコネクションプールが上限になる**ので、そちらと揃えないと意味がありません。

**Q72. `newFixedThreadPool` 을 프로덕션에서 안 쓰는 이유** ★변별력
> 内部のキューが**容量無制限**だからです。処理が追いつかないとタスクが際限なく溜まり、最終的に `OutOfMemoryError` になります。本番では `ThreadPoolExecutor` を直接組み立て、キュー容量と拒否ポリシーを明示します。

**Q75. 데드락은 왜 일어나고 어떻게 막나** ★가장 자주
> 複数のロックを**異なる順序**で取りに行き、互いに相手の解放を待つと起きます。一番実効性がある対策は**ロックの取得順序を全体で統一する**ことで、これだけで循環待ちが消えます。

---

### ④ JVM · 메모리

**Q90. Minor GC 와 Full GC 의 차이**
> Minor GC は Young 領域だけなので短時間で終わり、Full GC は Old まで含むので停止時間が長くなります。だから運用で見るべきは**Full GCの頻度と時間**です。

**Q96. Java 에도 메모리 누수가 있나** ★변별력
> あります。**不要になったのに参照が残っている**状態です。代表的なのは、`static` なコレクションへの追加、リスナーの登録解除漏れ、`ThreadLocal` の `remove` 忘れ、上限のないキャッシュの四つです。

**Q97. 메모리 누수 조사 순서** ★실무
> まずGCログで、**Full GCの後もヒープが減らない**ことを確認します。次にヒープヒストグラムを時間を空けて二回取り、増え続けているクラスを特定します。最後にヒープダンプで、**増えているものではなく、それを掴んでいるもの**を探します。

## 2. A급 — 자주 나온다 (27문항)

키노트는 한 줄씩만. 본문을 읽어 두면 충분하다.

| Q | 핵심 한 줄 |
|---|---|
| Q1 | `==` 는 참조, `equals` 는 값. `String` 이 `==` 로 되는 건 풀 공유 때문 |
| Q4 | 반복 조립은 `StringBuilder`. `StringBuffer` 는 동기화된 만큼 느림 |
| Q5 | **한 줄 `+` 는 컴파일러가 이미 `StringBuilder` 로 바꾼다.** 문제는 루프를 걸칠 때 |
| Q9 | `final` 변수는 **참조의 고정이지 내용의 불변이 아니다** |
| Q10 | `static` 은 참조가 계속 남아 GC 안 된다 → 누수의 단골 |
| Q11 | 오버로딩은 컴파일 시점, 오버라이딩은 실행 시점 결정 |
| Q12 | 다중 상속이 필요하면 인터페이스. 망설이면 인터페이스 |
| Q15 | Java 는 **항상 값 전달**. 객체는 "참조라는 값"이 복사됨 |
| Q19 | `try-with-resources` 는 **역순으로** 닫고, 억제 예외로 원인을 안 지운다 |
| Q22 | 타입 소거 → `new T[]` 불가, `instanceof List<String>` 불가 |
| Q23 | PECS — Producer `extends`, Consumer `super` |
| Q25 | `record` 는 암묵적 `final`, 필드도 `final` → JPA 엔티티에는 못 씀 |
| Q30 | 내부 클래스는 외부 참조를 암묵적으로 가짐 → 누수. 안 쓰면 `static` |
| Q32 | 실무는 거의 `ArrayList`. `LinkedList` 는 캐시 효율이 나빠 실측에서 짐 |
| Q37 | 리사이즈는 "용량 × 0.75" 초과 시. 건수를 알면 초기 용량 지정 |
| Q39 | `Hashtable` 은 안 씀. `ConcurrentHashMap` 은 버킷 단위 락 |
| Q45 | `ConcurrentModificationException` 은 **단일 스레드에서도** 난다 |
| Q47 | `List.of()` 는 복사한 불변, `unmodifiableList` 는 **원본이 바뀌면 같이 바뀜** |
| Q51 | `synchronizedList` 는 **순회는 안 지켜준다** |
| Q57 | `Callable` 은 예외를 `ExecutionException` 으로 전달 → 안 삼킴 |
| Q62 | happens-before 가 없으면 **쓴 값이 보인다는 보장이 없다** |
| Q63 | CAS 는 락 없이 재시도. 경합이 심하면 오히려 손해 |
| Q70 | `shutdown` → `awaitTermination` → `shutdownNow` 3단계 |
| Q74 | `Future.get()` 은 블로킹. `CompletableFuture` 에 **타임아웃 필수** |
| Q85 | `InterruptedException` 은 삼키지 말고, 못 던지면 `interrupt()` 로 복원 |
| Q104 | JIT — 워밍업 후 자릿수로 빨라짐. 벤치마크에 워밍업이 필수인 이유 |
| Q125 | `Optional` 은 **반환값에만**. `isPresent` + `get` 은 의미 없음 |

**여섯 개의 "아니오"** 를 기억하면 함정 질문은 대부분 막힙니다.

| 질문의 유혹 | 정답 |
|---|---|

| 한 줄 문자열 연결도 `StringBuilder` 로 바꿔야 하나? | **아니오** — 컴파일러가 이미 함 (Q5) |
| `finally` 에서 `return` 해도 되나? | **아니오** — 예외가 지워짐 (Q20) |
| `ConcurrentHashMap` 이면 `get`+`put` 도 안전한가? | **아니오** — 조합은 원자적이 아님 (Q40) |
