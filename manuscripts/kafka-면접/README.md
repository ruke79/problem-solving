# Kafka 면접 답변 스크립트 — Q1~Q50

[`java-면접/`](../java-면접/README.md)·[`spring-면접/`](../spring-면접/README.md) 과 같은 형식의 별도 세트다.
**일본어 답변 + 한국어 답변** 양쪽, 한 문항 **30~40초 분량**.

- **50문항 이내로 압축했다.** 설정 이름을 외우는 문항이 아니라 **왜 그 설정이 필요한가**를 묻는 형태로 골랐다.
- 문체는 다른 세트와 같은 **です・ます체**.

## 시간이 없다면 이 아홉 개

| | 문항 |
|---|---|
| 거의 반드시 | Q3 순서 보장의 범위 · Q5 컨슈머 그룹 · Q13 컨슈머를 늘리면 빨라지나 · Q12 랙 |
| 시니어면 반드시 | Q10 Exactly-Once 가 보장하지 **않는** 것 · Q15 독이 든 메시지 · Q26 Outbox · Q31 급증 흡수 |
| 준비된 사람이 적음 | Q14 키 편중과 그 대가(순서를 잃는다) |

**Q10 은 함정 질문에 가깝다.** "Exactly-Once 가 있으니 중복 대책은 필요 없다"고 답하면 감점이다.
**Kafka 안에서 완결되는 범위만 보장되고 외부 DB·API 로의 부수효과는 별개**라고 나눠 말해야 한다.

## 이 세트의 성격 — 답변의 근거

**실물 브로커(Kafka 3.9) 위에서 도는 케이스가 있다.** `verify-labs-kafka` 의 `KAFKA-01`~`07` 과
`verify-labs` 의 `MSA-*` 가 그것이다 — 흉내가 아니라 실제 파티션 재할당과 랙을 관측한다.

| 문항 | 실행 근거 |
|---|---|
| Q3 순서 보장 · Q24 Kafka vs RabbitMQ | `KAFKA-01` — 같은 키는 항상 한 파티션, 그 안에서 발행 순서가 유지된다 |
| Q12 랙 · Q31 급증 흡수 | `KAFKA-02` — 아무도 소비하지 않으면 랙은 발행 건수 그대로, 처리한 만큼만 준다 · `MSA-03` — 지속 초과면 랙이 선형으로 는다 |
| Q15 독이 든 메시지 · Q16 재시도 토픽 | `KAFKA-03` · `MSA-04` — **불량 메시지 하나가 뒤의 전부를 막는다**, 두 전략 모두 결국 전건을 처리한다 |
| Q9 프로듀서 멱등성 · Q10 EOS | `KAFKA-04` — 3.0+ 는 멱등성이 기본 활성, `read_committed` 는 커밋된 것만 본다 |
| Q5 컨슈머 그룹 · Q13 병렬도 | `KAFKA-05` — 컨슈머가 1대면 전 파티션을 혼자, 늘면 나눠 갖는다 |
| Q14 키 편중 | `KAFKA-06` — 편중되면 한 파티션만 몰리고 나머지는 거의 빈다 |
| Q19·Q20 스키마 진화 | `KAFKA-07` — 기본값 있는 필드 추가는 전방·후방 모두 호환 |
| Q26 Outbox | `MSA-01` — Outbox 없으면 발행 실패 시 복구 근거가 남지 않는다 |
| Q28 순서 없는 도착 | `MSA-02` — 무조건 덮어쓰면 늦게 온 옛 이벤트가 이긴다, 버전 가드가 막는다 |
| Q35 CDC | `DB-10` — 기본 identity 의 DELETE 에는 PK 만 남는다 |
| Q45 분산 트레이싱 | `OBS-01`·`OBS-02` — W3C `traceparent` 전파, 스레드가 바뀌면 MDC 가 끊긴다 |

**직접 돌려 보려면**: `./scripts/random-ports.sh && docker compose up -d --wait && ./gradlew :verify-labs-kafka:test`

## 검증하지 못한 것

- **브로커 장애·리더 선출·ISR 축소**(Q8·Q36·Q37) — 단일 브로커 구성이라 복제 인자 3 을 만들 수 없었다.
  `unclean.leader.election` 의 데이터 손실은 **문서 기준의 서술**이다.
- **KRaft 이행**(Q25)·**Kafka Streams**(Q34)·**보안 설정**(Q46) — 환경을 만들지 못했다.
- **처리량 수치** — 이 세트에는 "초당 몇 건" 같은 숫자를 쓰지 않았다. 재지 않은 것을 인용하지 않기 위해서다.
