# DB 면접 답변 스크립트 — Q1~Q50

[`java-면접/`](../java-면접/README.md)·[`spring-면접/`](../spring-면접/README.md) 과 같은 형식의 별도 세트다.
**일본어 답변 + 한국어 답변** 양쪽, 한 문항 **30~40초 분량**.

- **50문항 이내로 압축했다.** 특정 제품의 문법이 아니라 **어디서나 통하는 원리**를 골랐고,
  갈리는 부분은 "PostgreSQL 기준으로는" 처럼 전제를 밝히게 썼다.
- 문체는 다른 세트와 같은 **です・ます체**.

## 시간이 없다면 이 열 개

| | 문항 |
|---|---|
| 거의 반드시 | Q5 복합 인덱스 순서 · Q11 격리 수준 · Q15 데드락 · Q17 커넥션 풀 사이즈 · Q19 SQL 인젝션 |
| 시니어면 반드시 | Q20 키셋 페이징 · Q29 무중단 스키마 변경 · Q35 멱등성 · Q50 장애 조사 순서 |
| 준비된 사람이 적음 | Q13 쓰기 스큐 · Q36 분산 락의 펜싱 토큰 |

**Q17·Q18 은 세트로 준비하는 편이 좋다.** "풀을 늘리면 되지 않나"에 대해
**DB 쪽 상한과 대기열이 어디로 옮겨가는지**를 말할 수 있으면 그 자리에서 끝난다.

## 이 세트의 성격 — 답변의 근거

**이 세트는 다섯 세트 중 실행 근거가 가장 두껍다.** `verify-labs` 의 `DB-*` 25건이
실물 PostgreSQL 16(+ 스트리밍 레플리카)에서 도는 케이스이기 때문이다.

| 문항 | 실행 근거 |
|---|---|
| Q4·Q7 인덱스가 안 타는 경우 | `DB-03` — 인덱스 생성 전후 실행 계획 변화, 선택도에 따른 선택 |
| Q5 복합 인덱스 순서 | `DB-14` — 선행 컬럼 조건은 타고, 후행만이면 못 탄다 |
| Q11 격리 수준 | `DB-01` — READ COMMITTED 의 반복 불가능 읽기 vs REPEATABLE READ 의 스냅샷 |
| Q13 쓰기 스큐 | `DB-09` — REPEATABLE READ 에서 불변식이 깨지고 SERIALIZABLE 에서 한쪽이 취소된다 |
| Q15 데드락 | `DB-07` — 엇갈린 락 순서에서 락 타임아웃이 아니라 데드락(40P01) 이 난다 |
| Q17·Q18 커넥션 풀 | `DB-02`(고갈 시 타임아웃 실패) · `DB-06`(누수/점유/용량 구분) · `DB-18`(누수 탐지) |
| Q19 SQL 인젝션 | `DB-04`·`DB-19`·`SEC-05` — **바인딩할 수 없는 정렬 컬럼**까지 확인했다 |
| Q22 대량 삽입 | `PERF-11A` — 배치로 묶어 실측 36배 |
| Q26 파티셔닝 | `DB-08` — 파티션 키가 빠지면 전 파티션을 읽는다 |
| Q28 레플리카 | `DB-24` — 레플리카는 읽기 전용 |
| Q29 무중단 스키마 변경 | `DB-11`(상수 기본값 컬럼 추가는 즉시, 타입 변경은 재작성) · `MSA-05`(5단계 내내 구 버전이 동작) |
| Q34 캐시 스탬피드 | `RES-02` — `sync=true` 로 로딩이 1회로 묶인다 |
| Q35 멱등성 | `DB-12`·`RES-01` — 유니크 제약이 있으면 부수효과는 정확히 1회 |
| Q36 분산 락 | `DB-16` — **락만으로는 늦게 깨어난 쪽이 덮어쓴다**, 펜싱 토큰이 막는다 |
| Q37 Outbox | `MSA-01` — Outbox 없으면 발행 실패 시 복구 근거가 없다 |
| Q38 CDC | `DB-10` — 기본 identity 의 DELETE 에는 PK 만 남는다 |
| Q39 이벤트 소싱·CQRS | `DB-22` — 두 방식의 복원 결과 일치, 스냅샷 이후만 읽기 |
| Q42 전문 검색 | `DB-15` — 전방 일치는 인덱스를 타고 중간 일치는 전건 스캔 |
| Q44 이력 마스터 | `DB-20` — Type 1 은 과거 매출이 현재 가격으로 재계산된다 |
| Q45 멀티테넌시 | `DB-13` — RLS 를 켜면 조건을 빠뜨려도 자기 테넌트만 보인다 |
| Q47 배치 리커버리 | `DB-21` — 체크포인트가 없으면 처음부터 전건을 다시 돈다 |
| Q48 중복 실행 방지 | `DB-23` — 락이 없으면 노드 수만큼 중복 실행된다 |
| Q49 서버리스 접속 상한 | `DB-25` — 상한만큼만 성공하고 나머지는 **서버가** 거절한다 |
| Q2 PK 선택(UUID) | `DB-05` — UUIDv7 은 생성 순서대로 정렬되고 v4 는 무관 |

**직접 돌려 보려면**: `./scripts/random-ports.sh && docker compose up -d --wait && ./gradlew test -Dverify.only=DB-14`

## 검증하지 못한 것

- **MySQL·Oracle 고유 동작.** 이 저장소의 케이스는 전부 **PostgreSQL 16 기준**이다.
  InnoDB 의 갭 락(Q14)이나 클러스터 인덱스는 재현하지 않았다(`docs/02` §6-1). 면접에서 제품을 특정해
  물으면 "PostgreSQL 에서는 이렇게 확인했고, MySQL 은 문서 기준으로는" 이라고 나눠 말하는 편이 안전하다.
- **샤딩(Q27)·백업 복구(Q31)·OLAP(Q43)** — 환경을 만들지 못해 실행 근거가 없다.
