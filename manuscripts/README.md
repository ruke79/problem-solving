# 면접 답변 원고 (Q1~Q200)

이 디렉터리는 검증 랩(`verify-labs`)이 대조한 **원고 자체**를 보관한다.
지금까지는 원고가 저장소 밖에 있어서 랩이 지적만 하고 적용은 할 수 없었는데,
2026-08-13 에 저장소로 들여왔다.

## 세 벌이 있다

|  | `원본/` | `수정본/` | `회화체/` |

| **무엇인가** | 받은 그대로. 아무것도 고치지 않았다 | 원본 + `docs/10-원고-수정-지시서.md` 의 지적 8건·보강 9건 반영 | 수정본을 **말투만** 회화체로 다시 쓴 것 |

### 수정본 → 회화체 에서 바뀐 것 / 바뀌지 않은 것

| 바뀐 것 (말투) | 바뀌지 않은 것 (내용) |
|---|---|
| 한 문장을 짧게 끊음 — 문어체 한 문장이 두세 문장이 됨 | 기술적 주장과 결론 |
| "~하며", "~로써", "~인 반면" → "그리고", "그래서", "대신에" | 모든 수치와 측정값 |
| 한자어를 입에 붙는 말로 (담보한다 → 보장한다) | Q번호 상호 참조 (→ Q54, Q100 …) |
| 실제로 말할 때 쉬는 지점에서 문단을 나눔 | 재출제 표시와 ⚠️ 주석 |
| — | 정중함 (**~습니다** / **です・ます**). 면접이니까 |

전체 방침은 `회화체/Part1.md` 머리말에 적어 두었다.

**예외 한 건** — `회화체/Part11.md` 의 Q170~190 은 굵은 글씨를 그대로 남겼다.
원고 저자가 "굵은 부분이 다른 지원자와 차이를 만드는 지점"이라고 명시한 의도적 강조라서,
지적 ⑤ 의 대상이 아니었고 회화체에서도 건드리지 않았다.

## 원본에 대한 고지

- **Part 1·2·7·8·9·10·11** — markdown 으로 받았다. `원본/PartN.md` 가 받은 파일 그대로다.
- **Part 3·4·5·6** — PDF 로 받았다. PDF 는 저장소에 넣지 않고, 텍스트 추출 결과를
  `원본/PDF-추출-Part3-6/` 에 두었다. **PDF 줄바꿈 지점의 띄어쓰기는 추출 단계에서
  소실된다** — 그래서 이 네 파트의 `수정본/` 에는 단어 중간에 어색한 공백이 남아 있을 수 있다.
  자동 교정을 시도했다가 오히려 필요한 공백을 지우는 사고가 나서 되돌렸고, 대신 각 파일
  머리말에 고지를 넣어 두었다.

## 무엇이 고쳐졌나

`수정본/00-적용-내역.md` 에 A(사실 오류)·B(실물 미재현)·C(표현)·D(보강) 별로 정리돼 있다.
지적의 근거가 된 검증 케이스는 `docs/10-원고-수정-지시서.md` 에서 찾을 수 있고,
각 케이스는 `./gradlew test` 로 다시 돌려 숫자를 직접 확인할 수 있다.

## 일본어 전수 조사 — 동사 · 조사 · 경어 (2026-08-31)

`수정본/` 의 일본어 답변에서 **동사 539종(총 5,995회)** 과 **한자어+する 425종** 을 형태소
분석기로 전수 추출해 검토하고, **11곳을 고쳤다**(`회화체/` 에도 10곳 반영 — 나머지 1곳은
회화체가 이미 맞게 되어 있었다). 상세와 근거는 [`docs/12-일본어-동사-전수-조사.md`](../docs/12-일본어-동사-전수-조사.md).

- **확정 오류 1건** — `リタイア`(은퇴) → `リトライ`(재시도). **`원본/` 에도 있는 원고 유래 오류**다.
- **연어 불일치 6건** — `リクエストが襲う` → `押し寄せる` 등.
- **격식 4건** — `即死` → `即座にダウン`, `時間を溶かす` → `時間を費やす` 등.
- **일부러 두지 않은 것이 더 많다** — `全件を舐める`·`Redisを噛ませる`·`ノードが死ぬ` 등은
  실제로 일본 엔지니어가 쓰는 말이라 과잉 교정하지 않았다.

**이어서 조사(助詞)·경어도 같은 방식으로 훑었다.** 문말 체 1,881개 분류 + 경어 오류 6종 +
조사 격지배 검사 — 후보 **129건 중 진짜 오류는 1건**이었다(`障害を対応` → `障害に対応`,
한국어 "장애를 대응하다"의 간섭). `貴社`/`御社` 구분은 200문항 내내 지켜지고 있었다.

- **常体 40건은 고치지 않았다** — 「…高い。だから…します。」처럼 강조 뒤 敬体로 받는 일관된 수사다.
- **오탐률 99.2%** 가 이 조사의 가장 큰 결과다. `〜の方が`(비교)를 바이트경어로,
  `集中させる`(사역)를 격지배 오류로 잡는 식이었다. **그대로 적용했으면 멀쩡한 문장 128곳을 고쳤다.**

> **이 조사는 실행으로 판정할 수 없다.** 추출은 기계적이고 재현 가능하지만
> **자연스러움 판정은 의견이며, 원어민 검수를 대체하지 않는다**(`docs/12` §0).
> 이 랩의 `CONFIRMED` 와 같은 수준의 근거로 취급하면 안 된다.
> 특히 **は/が 의 선택은 아예 검사하지 못했다** — 이 원고에서 가장 미검증인 영역이다.

## `java-면접/` — 별도 세트 (Q1~Q145, 2026-08-31)

위 세 벌(`원본`·`수정본`·`회화체`)과는 **다른 원고**다. 저쪽이 시니어 면접 전 범위(아키텍처·데이터·
조직)라면, 이쪽은 **Java 언어와 런타임에 집중**한 145문항이다. 답변은 **30~40초 분량으로 짧다.**

| Part | 범위 | 문항 |
|---|---|---|
| 1 | 자바 언어 기초 | Q1~Q30 |
| 2 | 컬렉션 프레임워크 | Q31~Q55 |

| 5 | 모던 자바와 실무 | Q116~Q145 |

동일한 형식의 **`spring-면접/`(Q1~Q145)** 도 있다 — 코어·DI / AOP·트랜잭션 / Web·MVC /
데이터 접근 / 운영·테스트·보안. **이쪽은 `SPRING-*`·`JPA-*`·`SEC-*`·`RES-*` 케이스가
실행 근거인 문항이 25개 이상**이라, 세 세트 중 근거가 가장 두껍다.

상세는 [`java-면접/README.md`](java-면접/README.md) · [`spring-면접/README.md`](spring-면접/README.md).

**두 세트 모두 `필수-키노트.md` 가 있다** — 145문항을 **S급 18 / A급 27 / B급**으로 나누고,
S급에는 **그대로 외울 수 있는 일본어 한 문장**을 붙였다. 시간이 부족할 때는 그것만 보면 된다.
각 키노트 끝에 「면접 30분 전 최종 점검」으로 **함정 질문의 "아니오" 목록**을 정리해 뒀다. **일부 문항은 `verify-labs-perfbook` 의
`PERF-*` 케이스가 실행 근거이고, 반대로 검증하지 못한 문항도 그 README 에 명시했다** —
면접에서 수치를 인용할 때 직접 측정한 것인지 구분하기 위해서다.

`docs/12` 의 일본어 검사를 이 원고에도 돌려 **조사 오용 0건 · 문말 체 통일**을 확인했다.

## `면접-용어-정의.md` — Java·Spring 용어 사전

[`면접-용어-정의.md`](면접-용어-정의.md) 는 `java-면접`·`spring-면접` **290문항의 제목을 전수로 훑어**
실제로 나오는 용어만 모은 사전이다. 각 항목은 **한국어 용어 · 日本語 표기 · 정의 · 나오는 문항과 케이스 id** 로 되어 있다.

- **日本語 열이 있는 이유** — 한국식 한자어를 그대로 읽으면 통하지 않는 것이 많다(지연 로딩 → `遅延ローディング`,
  멱등성 → `冪等性(べきとうせい)`, 기아 → `スターベーション`).
- **면접에서 가장 흔한 실수는 모르는 것이 아니라 비슷한 두 개를 섞는 것**이라, 경계가 헷갈리는 짝
  (가시성/원자성, 인증/인가, 낙관 락/비관 락, liveness/readiness)을 나란히 두었다.
- 버전에 매인 용어는 [`../notes/JVM-용어-변천사.md`](../notes/JVM-용어-변천사.md) 에 연표로 따로 있다.

> 손으로 베끼면 키노트를 고쳤을 때 조용히 어긋나고 **어긋난 쪽을 외우게 되기** 때문이다.
> CI 의 `docs` 잡이 `--check` 로 어긋남을 실패로 잡는다.
