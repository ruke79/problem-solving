# Python 면접 — 필수 문항 지정과 키노트

> **시간이 부족할 때 이 파일만 보면 된다.** 50문항을 세 등급으로 나누고,
> S급에는 **일본어 한 문장**을 붙였다. 그 문장만 외워도 답이 성립한다.
>
> 등급 기준은 **출제 빈도 × 변별력**이다. 자주 나오는데 남들도 다 아는 것보다,
> **자주 나오는데 절반은 틀리는 것**을 위로 올렸다.
>
> ⚠️ **이 세트에는 실행 근거가 없다.** 이 저장소의 검증 모듈은 전부 JVM 기반이라,
> 파이썬 문항에는 `PERF-*` 같은 케이스 id 를 붙일 수 있는 것이 없다([`README.md`](README.md) 참고).
> **그래서 수치를 말하지 않는 답변으로 썼다.** 면접에서 숫자를 인용해야 한다면
> 그 자리에서 잰 것인지 읽은 것인지 밝히는 편이 안전하다.

## 1. S급 — 반드시 나온다 (10문항)

### ① GIL 과 동시성 — 파이썬 면접의 핵심

**Q14. GIL 이란 무엇이고 무엇이 제한되나** ★가장 자주
> CPython のインタプリタが同時に一つのスレッドしか Python バイトコードを実行させない仕組みです。制限されるのは **CPU バウンドの並列化**で、I/O 待ちの間は GIL が解放されるので、ネットワークやファイル待ちが多い処理はスレッドでも効果があります。

**Q15. 스레드·프로세스·asyncio 를 어떻게 고르나** ★가장 자주
> 判断の起点は「待っているのか、計算しているのか」です。I/O バウンドで接続数が多いなら asyncio、既存のブロッキングライブラリを使うならスレッド、CPU バウンドなら `multiprocessing` でプロセスに分けます。

**Q16. `async`/`await` 를 쓸 때 가장 조심할 것** ★실무 함정
> **コルーチンの中でブロッキング処理を呼ぶとイベントループ全体が止まる**ことです。同期的なライブラリを使うなら `run_in_executor` でスレッドに逃がします。

> **Q14·Q15 는 반드시 세트로 준비한다.** "GIL 이 있으니 파이썬은 느리다"로 끝내면 감점이다.
> **무엇이 제한되고 무엇은 제한되지 않는가**를 나눠 말해야 한다.

---

### ② 가변성과 복사 — 가장 흔한 함정

**Q2. 기본 인자에 리스트를 지정하면** ★함정
> デフォルト値は関数の定義時に一度だけ評価されるので、呼び出しをまたいで同じオブジェクトが使い回されます。対策は `None` を既定にして、関数の中で `if x is None: x = []` とすることです。

**Q3. 얕은 복사와 깊은 복사** ★함정
> 浅いコピーは一段目だけを新しく作り、中の要素は元と同じオブジェクトを参照します。ネストした構造を浅くコピーすると内側の変更が元にも及ぶので、必要なときだけ `copy.deepcopy` を使い、そもそも不変にする設計を優先します。

---

### ③ 메모리와 성능

**Q26. CPython 의 메모리 관리** ★가장 자주
> 基本は参照カウントで、参照が 0 になった瞬間に解放されます。ただし**循環参照は参照カウントでは消えない**ので、世代別のガベージコレクタが補います。

**Q8. 제너레이터의 장점**
> 値を一度に全部作らず必要になったときに一つずつ返すので、**メモリを要素数に比例させずに済みます**。巨大なファイルの行処理や無限に続く数列を扱えます。ただし一度しか回せません。

**Q30. `lru_cache` 를 쓸 때의 함정** ★변별력
> `maxsize=None` は無制限なので、引数の種類が多い関数に付けるとそのままメモリリークになります。インスタンスメソッドに付けると `self` を掴んでオブジェクトが解放されない点も要注意です。

---

### ④ 실무 — 여기서 갈린다

**Q33. `pickle` 의 위험** ★보안
> **信頼できないデータを `pickle.loads` すると任意のコードが実行されます。**外部から来たデータには絶対に使わず、用途を内部のキャッシュやプロセス間通信に限ります。

**Q40. 외부 API 를 부를 때 반드시 하는 것** ★실무 함정
> タイムアウトの設定です。`requests` はデフォルトで無期限なので、指定しないと相手が応答しないだけでこちらのワーカーが枯渇します。

## 2. A급 — 자주 나온다 (15문항)

| Q | 한 줄 |
|---|---|
| Q1 | 리스트는 가변, 튜플은 불변 → 튜플만 딕셔너리 키가 된다 |
| Q4 | `is` 는 동일 객체, `==` 는 값. `is` 는 **`None` 판정에만** |
| Q5 | 딕셔너리는 해시 테이블. 삽입 순서 보장은 **3.7 부터 언어 사양** |
| Q6 | 키는 해시 가능해야 한다 — `__eq__` 를 정의했으면 `__hash__` 도 함께 |
| Q9 | 이터러블은 `__iter__`, 이터레이터는 `__next__` + 상태를 가짐 |
| Q10 | 클로저가 잡는 것은 **값이 아니라 변수** → 루프에서 전부 마지막 값 |
| Q11 | 데코레이터에는 `functools.wraps` 를 반드시 |
| Q13 | 스코프는 LEGB. `global`·`nonlocal` 이 필요하면 설계를 의심 |
| Q17·Q18 | `else` 는 성공 시만, `finally` 는 항상. 뒷정리는 `with` 로 |
| Q20 | MRO 는 C3 선형화 → `super()` 는 부모가 아니라 **MRO 의 다음** |
| Q22 | 구조가 정해졌으면 `dataclass`. 딕셔너리를 타입처럼 쓰지 않는다 |
| Q25 | 타입 힌트는 **런타임에 무시된다** — mypy 를 CI 에서 돌려야 의미가 생긴다 |
| Q27 | 누수는 전역 캐시·`__del__` 이 얽힌 순환·무제한 `lru_cache`. 조사는 `tracemalloc` |
| Q28 | 프로파일링 전에 **DB/API/파이썬 중 어디가 느린지부터** 가른다 |
| Q31 | 루프 안 `+=` 대신 `"".join()`. 쿼리는 애초에 바인딩으로 |

## 3. B급 — 나오면 가산점 (준비된 사람이 적다)

| Q | 왜 차별점인가 |
|---|---|
| **Q23 `__slots__`** | `__dict__` 를 없애 메모리를 줄인다 — 대량 객체에서만 의미 |
| **Q24 Protocol** | ABC 는 상속 강제, **Protocol 은 구조만으로** 타입을 맞춘다 |
| **Q32 `deque`** | 리스트의 `pop(0)` 은 O(n), `deque.popleft()` 는 O(1) |
| **Q36 WSGI/ASGI** | ASGI 로 바꿔도 **안에서 블로킹하면 의미가 없다** |
| **Q37 gunicorn 워커 수** | 워커 수 × DB 커넥션이 **DB 상한을 넘지 않는지**까지 말하면 갈린다 |
| **Q45 `subprocess`** | `shell=True` 가 위험. 인자는 리스트로 넘긴다 |
| **Q47 부동소수점** | 금액은 `Decimal` 이나 정수 최소 단위. 비교는 `math.isclose` |
| **Q50 GIL 제거 논의** | "당분간 기존 전제로 설계한다"는 신중한 태도가 오히려 높게 평가된다 |

## 4. 면접 30분 전 최종 점검 — 이것만은

**다섯 개의 "아니오"** 를 기억하면 함정 질문은 대부분 막힙니다.

| 질문의 유혹 | 정답 |
|---|---|
| 기본 인자에 `[]` 를 써도 되나? | **아니오** — 호출 간에 공유됨 (Q2) |
| GIL 때문에 스레드는 아무 의미 없나? | **아니오** — I/O 대기 중에는 풀린다 (Q14) |
| `async` 로 감싸면 다 빨라지나? | **아니오** — 안에서 블로킹하면 루프가 멈춘다 (Q16) |
| 타입 힌트를 쓰면 런타임에 검사되나? | **아니오** — 무시된다, mypy 가 필요 (Q25) |
