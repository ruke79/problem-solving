# Java Performance: The Definitive Guide — 장별 요약

Scott Oaks, *Java Performance: The Definitive Guide* (O'Reilly) 의 **장별 상세 요약**이다.
각 파일은 그 장의 논지·수치·표를 한국어로 옮긴 것이고, 마지막에
**"이 장을 우리 랩에 비춰 보면"** 표가 붙어 있다 — 이 저장소의
[`interview-verify-lab`](../../verify-labs) 검증 케이스 중 **무엇이 이 장의 주장을 실제로
실행해서 확인했고, 무엇이 확인되지 않은 채 남아 있는지**를 대조한 표다.

> **정직한 고지 1 — 1장이 없다.**
> 요약의 바탕이 된 업로드 자료에 **1장(Introduction)이 포함되어 있지 않았다.**
> 그래서 이 폴더는 **2장~12장 + 부록 A** 를 다룬다. 1장은 읽지 않았으므로 요약하지 않았다.
>
> **정직한 고지 2 — PDF 에서 추출한 텍스트가 원본이다.**
> 표가 많은 장(특히 부록 A)은 PDF 추출 과정에서 칸이 줄바꿈으로 흩어졌다.
> 의미가 확실한 것만 옮겼고, **끊긴 문장을 추측으로 메우지 않았다.**
>
> **정직한 고지 3 — 이 책은 JDK 7/8 시절에 쓰였다.**
> permgen/메타스페이스, `UnlockCommercialFeatures`, 편향 락처럼
> **이후 JDK 에서 사라지거나 바뀐 것들이 있다.** 그런 항목은 해당 파일 안에서
> 따로 짚어 두었다.

## 이 요약을 왜 이 저장소에 뒀나

이 저장소의 [`interview-verify-lab`](../../README.md) 은
**"면접 답변을 실제로 실행해서 확인한다"** 를 원칙으로 한다
(`docs/00-인계-노트.md` §8 — **정직성 우선, "검증한 척"을 만들지 않는다**).

이 책은 그 원칙과 결이 같다. 저자가 반복해서 하는 말이

> **"측정하지 않은 최적화는 최적화가 아니다"**
> **"플래그로 고칠 수 있다는 말은 대개 코드를 못 고칠 때 하는 말이다"**

이기 때문이다. 그래서 각 장 요약 끝에 붙인
**"이 장을 우리 랩에 비춰 보면"** 표는 **자랑이 아니라 구멍 목록**에 가깝다.
표에 "검증 케이스 **없음**" 이라고 적힌 줄이, **이 랩이 아직 실행해 보지 않은 주장**이다.

그 구멍 목록은 [`docs/02-정직한-고지.md`](../../docs/02-정직한-고지.md) §9 에서
전수 분류됐고("못 하는 것 / JDK 가 없앤 것 / 별도 JVM / 안 한 것"),
**"안 한 것" 대부분은 [`verify-labs-perfbook`](../../verify-labs-perfbook) 모듈의
케이스 15건(`PERF-*`)이 됐다** — 이 책의 명제를 실제 실행으로 확인한다.

```
./gradlew :verify-labs-perfbook:test                        # 전부 (PERF-11* 은 PostgreSQL 필요)
./gradlew :verify-labs-perfbook:test -Dverify.only=PERF-12  # 12장만
```

> `PERF-10C`(10장 "출력을 줄여라")만 예외로 **원격 배포본이 있어야 단정한다** —
> 로컬에서는 INCONCLUSIVE 로 남는 것이 설계다(`docs/02` §9-6, `docs/11` §5).
