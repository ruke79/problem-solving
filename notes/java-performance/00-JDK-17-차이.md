# 책과 JDK 17 의 차이 — 장별 대조

> Scott Oaks, *Java Performance: The Definitive Guide* 는 **JDK 7/8 시절**에 쓰였다.
> 이 문서는 **그 내용 중 JDK 17 에서 달라진 것을 장별로 정리한 것**이다.
>
> **이 문서를 만든 계기 — 내 README 가 과장돼 있었다.**
> [`README.md`](README.md) 의 정직한 고지 3번에 *"그런 항목은 해당 파일 안에서 따로
> 짚어 두었다"* 라고 써 뒀는데, 실제로 세어 보니 **13개 파일 전체에서 버전 차이를
> 짚은 곳이 4곳뿐이었다**(6장의 iCMS·AggressiveHeap, 부록 A 의 `UnlockCommercialFeatures`,
> 그리고 랩 대조표의 `UseContainerSupport` 행). "짚어 두었다"고 할 수 있는 상태가 아니었다.
> 그래서 이 문서를 따로 만들고, README 의 문장도 고쳤다.

## 0. 확인 방법과 그 한계

이 저장소의 원칙(`docs/00` §8)대로, **기억이 아니라 실행으로 확인한 것과
확인하지 않은 것을 갈라 적는다.**

- ✅ **표시가 있는 항목은 이 문서를 쓰면서 JDK 17.0.19 에서 직접 실행해 확인했다.**
  명령과 출력은 §3 에 그대로 실었다.
- 표시가 없는 항목은 **문서·릴리스 노트에 근거한 서술이고 실행으로 확인하지 않았다.**
  특히 "성능이 좋아졌다" 류는 **하나도 측정하지 않았다** — §4 참고.

```
$ /usr/lib/jvm/java-17-openjdk-amd64/bin/java -version
openjdk version "17.0.19" 2026-04-21
OpenJDK Runtime Environment (build 17.0.19+10-1-24.04.2-Ubuntu)
OpenJDK 64-Bit Server VM (build 17.0.19+10-1-24.04.2-Ubuntu, mixed mode, sharing)
```

## 2. 장별 상세

### 3장 — 성능 도구 상자

| 책 | JDK 17 |
|---|---|
| `jhat` 으로 힙 덤프 분석 | ✅ **`jhat` 이 없다**(JDK 9 제거). Eclipse MAT·VisualVM 을 쓴다 |
| JFR 은 상용 기능 — `-XX:+UnlockCommercialFeatures` 필요 | ✅ **그 플래그가 인식되지 않는다.** JFR 은 JDK 11 부터 오픈소스라 그냥 쓴다 |
| `-XX:+PrintGCDetails -XX:+PrintGCTimeStamps` 로 GC 로그 | ✅ **`PrintGCTimeStamps` 는 제거**됐고, `PrintGCDetails` 는 남아 있지만 **경고를 내고 `-Xlog:gc*` 로 넘긴다** |
| JMC 가 JDK 에 포함 | JMC 는 **별도 배포**(JDK 11 부터 분리) |
| `jcmd`·`jstack`·`jinfo` | 그대로. `jcmd` 권장이 더 강해졌고 **`jfr` CLI 가 추가**됐다 |

> **통합 로깅(JEP 158, JDK 9)이 이 장에서 가장 큰 변화다.** 책의 GC 로그 읽는 법은
> 개념은 그대로지만 **명령과 출력 형식이 다르다.** 지금은 이렇게 쓴다.
> ```bash
> -Xlog:gc*:file=gc.log:time,uptime,level,tags:filecount=5,filesize=10M
> ```

### 4장 — JIT 컴파일러

| 책 | JDK 17 |
|---|---|
| 클라이언트/서버 컴파일러를 `-client`·`-server` 로 고른다 | ✅ **`-client` 는 조용히 무시된다**(에러도 안 난다). 32비트 client VM 은 JDK 9 에서 제거 |
| 계층형 컴파일은 선택 사항 | ✅ **`TieredCompilation = true` 가 기본** |
| `-d64` | 제거(JDK 9). 64비트만 남았다 |
| 코드 캐시가 하나 | **분할 코드 캐시**(JDK 9) — non-nmethod / profiled / non-profiled 로 나뉜다 |
| — | **Graal JIT 는 JDK 17 에 없다**(JEP 410 으로 제거). AOT(`jaotc`)도 ✅ **없다** |

> 인라이닝·이스케이프 분석·역최적화·OSR·워밍업 같은 **개념 설명은 전부 그대로 유효하다.**
> 바뀐 것은 "어떤 컴파일러를 고르느냐"는 층뿐이고, 지금은 **고를 일이 없다.**

### 5장 — GC 입문 · 6장 — GC 알고리즘

**이 두 장이 가장 크게 어긋난다.**

| 책 | JDK 17 |
|---|---|
| 기본 수집기는 처리량(Parallel) 컬렉터 | ✅ **기본은 G1** (`[info][gc] Using G1`) |
| CMS 를 `-XX:+UseConcMarkSweepGC` 로 켠다 | ✅ **`Unrecognized VM option`.** CMS 는 JDK 14 에서 **삭제**됐다 |
| CMS 의 영 수집은 `-XX:+UseParNewGC` | ✅ **인식되지 않는다**(JDK 10 제거) |
| 처리량 컬렉터는 `-XX:+UseParallelOldGC` 를 함께 | ✅ **인식되지 않는다**(JDK 15 제거). `UseParallelGC` 만 주면 된다 |
| 수집기는 네 가지(Serial·Parallel·CMS·G1) | **Serial·Parallel·G1 + ZGC·Shenandoah·Epsilon** — ✅ 셋 다 이 JDK 에서 기동된다 |
| iCMS(`-XX:+CMSIncrementalMode`) | 제거. 책도 이미 "Java 8 폐기 예정"이라 적어 뒀다 |
| permgen 을 위한 CMS 튜닝 | permgen 자체가 없다(JDK 8 메타스페이스) |

> **6장의 CMS 절(동시 사이클 6단계 · 동시 모드 실패 · 승격 실패 · 단편화 · iCMS)은
> 이제 실행할 수 없는 내용이다.** 다만 **버리기엔 아까운 이유**가 있다 —
> "동시 수집기가 왜 실패하는가"의 구조는 G1 의 대피 실패(to-space exhausted)나
> ZGC 의 할당 정체(allocation stall)를 이해하는 데 그대로 쓰인다.
> **읽을 때 "CMS" 를 "동시 수집기 일반"으로 바꿔 읽으면 여전히 유효한 설명이다.**
>
> G1 부분(리전·혼합 GC·거대 객체·테뉴어링·TLAB)은 **지금도 그대로 유효**하고,
> 오히려 JDK 12 의 중단 가능 혼합 수집, JDK 14+ 의 NUMA 인식처럼 **개선만 더해졌다.**

### 7장 — 힙 메모리 모범 사례

| 책 | JDK 17 |
|---|---|
| `String` 은 `char[]` — 한 글자 2바이트 | ✅ **`String.value` 가 `byte[]`**(Compact Strings, JDK 9). **ASCII 10자 = 10바이트**(책 시절 20바이트) |
| `StringTableSize` 기본 1009 | ✅ **기본 65536.** 책의 "인터닝을 많이 하면 반드시 키워라"는 **전제가 약해졌다** |
| permgen 부족 → `PermSize`/`MaxPermSize` | ✅ **두 플래그 모두 인식되지 않는다.** 메타스페이스는 `MaxMetaspaceSize` |
| — | **문자열 중복 제거**(`-XX:+UseStringDeduplication`)가 추가됐다(G1 은 JDK 8u20+) |

> 소프트/위크/팬텀 레퍼런스, retained/shallow/deep size, 객체 풀 vs 스레드 로컬,
> OOM 네 가지 원인 — **이 절들은 전부 그대로 유효하다.**

### 8장 — 네이티브 메모리

거의 그대로 유효하다. **압축 oop 의 32GB 경계도 ✅ 그대로**(`UseCompressedOops = true`).

**책에 아예 없는 주제가 하나 생겼다 — 컨테이너 인식.**
JDK 10 부터 JVM 이 cgroup 을 읽어 컨테이너 메모리 한도를 인식한다(`UseContainerSupport`).
`-XX:MaxRAMPercentage` 로 비율 지정하는 것이 지금의 실무이고, 이 랩의 `JVM-07` 이 확인한다.

### 9장 — 스레딩과 동기화

| 책 | JDK 17 |
|---|---|
| 편향 락이 기본이고, 스레드 풀에서는 `-XX:-BiasedLocking` 이 도움이 된다 | ✅ **`UseBiasedLocking = false` 가 기본.** 플래그는 남아 있지만 주면 *"deprecated in version 15.0"* 경고가 난다. ✅ **JDK 21 에서는 옵션 자체가 인식되지 않는다**(17 과 21 만 확인 — 정확히 몇에서 없어졌는지는 §4-2 참고) |
| 거짓 공유는 `@sun.misc.Contended` 로 | ✅ **`sun.misc.Contended` 는 없다**(`ClassNotFoundException`). `jdk.internal.vm.annotation.Contended` 로 옮겼고 **`--add-exports` 없이는 못 쓴다** |
| 스레드 풀 크기는 코어 수 기준으로 산정 | 유효. 다만 **가상 스레드(JDK 21)가 이 전제를 바꾼다** — 책에는 없는 주제 |

> `ForkJoinPool`·작업 훔치기·암달의 법칙·CAS vs `synchronized`·`LongAdder` 는
> **전부 그대로 유효하다.** 이 랩의 `PERF-09A`(거짓 공유)·`PERF-09B`(암달의 법칙)가
> 그 위에서 돈다.

### 10장 — Java EE 성능

**성격이 다른 종류의 차이다.** 원리(출력 줄이기·세션 복제 비용·파서 팩토리 조회 비용·
지연 압축 해제)는 지금도 유효한데, **예제의 전제가 JSP/EJB 라 현재 실무와 멀다.**

- `javax.servlet.*` → **`jakarta.servlet.*`** (Jakarta EE 9 의 패키지 전면 변경).
  Spring Boot 3 이 이 전환을 강제한 것이 바로 이것이다.
- 이 랩은 이 장을 **Spring Boot 로 옮겨 검증한다** — `PERF-10A`(직렬화 참조 함정) ·
  `PERF-10B`(지연 압축 해제) · `PERF-10C`(원격 출력 다듬기).

### 11장 — 데이터베이스 성능

**가장 변화가 적다.** prepared statement 풀, 커넥션 풀 크기, 트랜잭션 격리와 배치,
JPA L1/L2 캐시와 `JOIN FETCH` 의 L2 우회 — 전부 그대로다.
`javax.persistence` → `jakarta.persistence` 와, 커넥션 풀 표준이 HikariCP 가 된 것 정도가 다르다.

### 12장 — Java SE API 팁

| 책 | JDK 17 |
|---|---|
| 컴파일러가 문자열 연결을 `StringBuilder` 로 바꾼다 | ✅ **`invokedynamic makeConcatWithConstants` 로 바뀐다**(JEP 280, JDK 9). 바이트코드에 `StringBuilder` 가 없다 |
| `String` 메모리 계산 | Compact Strings 로 **Latin-1 문자열은 절반**(7장 참고) |
| 예외 비용은 스택 트레이스 수집 | 그대로 유효. 이 랩의 `PERF-12B` 가 확인한다 |
| 버퍼드 I/O, 지연 스트림 순회, 로깅, 컬렉션 크기, 람다 | **전부 그대로 유효.** `PERF-12A`·`PERF-12C` 가 확인한다 |

> **결론이 바뀐 것은 아니다.** "한 줄짜리 `+` 를 손으로 `StringBuilder` 로 바꾸지 마라"는
> 조언은 **지금도 맞다** — 이유가 "컴파일러가 `StringBuilder` 로 바꿔 주니까"에서
> "컴파일러가 `invokedynamic` 으로 더 잘 바꿔 주니까"로 달라졌을 뿐이다.

### 부록 A — 튜닝 플래그 요약

**표에 실린 플래그 중 이 JDK 에서 아예 인식되지 않는 것들이 있다** — §3 의 실행 결과 참고.
이 랩의 `PERF-A01`(VanishedFlagsCase)이 그중 일부를 케이스로 만들어 상시 확인한다.

## 3. JDK 17.0.19 에서 실행해 확인한 것

### 3-1. 책이 권하는 옵션을 그대로 주면

```
$ java -XX:+UseConcMarkSweepGC -version   → Unrecognized VM option 'UseConcMarkSweepGC'
$ java -XX:+UseParNewGC        -version   → Unrecognized VM option 'UseParNewGC'
$ java -XX:+UseParallelOldGC   -version   → Unrecognized VM option 'UseParallelOldGC'
$ java -XX:PermSize=64m        -version   → Unrecognized VM option 'PermSize=64m'
$ java -XX:+UnlockCommercialFeatures -version → Unrecognized VM option 'UnlockCommercialFeatures'
```

**다섯 개 전부 기동 자체가 실패한다.** 경고가 아니라 에러다.

### 3-2. 기본값이 바뀐 것

```
$ java -Xlog:gc -version
[0.006s][info][gc] Using G1                    ← 책 시절 기본은 Parallel

$ java -XX:+PrintFlagsFinal -version | grep -w ...
UseBiasedLocking  = false      ← 책: 기본 true, "풀에서는 꺼라"
StringTableSize   = 65536      ← 책: 1009
UseCompressedOops = true       ← 그대로
TieredCompilation = true       ← 책: 선택 사항
AggressiveHeap    = false      ← 플래그는 남아 있다(여전히 비권장)
```

### 3-3. 제거·이동된 것

```
$ ls $JAVA_HOME/bin | grep -E 'jhat|jaotc'    → (없음)
$ java -XX:+PrintGCDetails -version
[0.001s][warning][gc] -XX:+PrintGCDetails is deprecated. Will use -Xlog:gc* instead.

sun.misc.Contended                        → ClassNotFoundException
jdk.internal.vm.annotation.Contended      → 존재

$ java -XX:+UseBiasedLocking -version           # JDK 17
OpenJDK 64-Bit Server VM warning: Option UseBiasedLocking was deprecated in
version 15.0 and will likely be removed in a future release.

$ java -XX:+UseBiasedLocking -version           # JDK 21
Unrecognized VM option 'UseBiasedLocking'
```

### 3-4. 새로 생긴 것

```
$ java -XX:+UnlockExperimentalVMOptions -XX:+UseZGC        -version  → 기동 성공
$ java -XX:+UnlockExperimentalVMOptions -XX:+UseShenandoahGC -version → 기동 성공
$ java -XX:+UnlockExperimentalVMOptions -XX:+UseEpsilonGC  -version  → 기동 성공
```

### 3-5. String 표현 (Compact Strings)

```
String.value 의 타입 = byte[]        ← 책 시절 char[]
java.lang.StringLatin1 존재 = true

ASCII  10자 → value 10 바이트        ← 책 시절 char[] 로는 20 바이트
한글    5자 → value 10 바이트        ← UTF16 이라 2바이트/자 그대로
```

### 3-6. 문자열 연결의 바이트코드

```java
static String f(String a, int b) { return "x=" + a + b; }
```
```
$ javap -c -p C.class
2: invokedynamic #7,  0   // InvokeDynamic #0:makeConcatWithConstants:(...)
```
**`StringBuilder` 가 바이트코드에 나타나지 않는다.**

## 4. 확인하지 않은 것 — 정직한 고지

1. **성능이 좋아졌다는 주장은 하나도 측정하지 않았다.** "G1 이 개선됐다", "ZGC 가
   정지 시간이 짧다" 같은 것은 **문서에 근거한 서술일 뿐 이 문서를 위해 재 본 적이 없다.**
   이 랩에서 시간을 재는 것은 `verify-labs-perfbook` 뿐이고, 그것도 `docs/02` §1-2 의
   해상도·최소 마진 규칙을 지킨 범위에서만 단정한다.
2. **JDK 18~25 의 변화는 이 문서 범위 밖이다.** 이 저장소의 기준이 JDK 17 이라 거기까지만 봤다.
   17 이후에도 움직이는 항목은 본문에 적었지만, **이 머신에 설치된 JDK 가 17 과 21 뿐이라
   "정확히 몇에서 없어졌는지"는 확인할 수 없었다.** 편향 락이 그 예다 — **17 에 경고와 함께 있고
   21 에 없다**까지만 실행으로 확인했다. `docs/02` §9-2 에는 원래 "JDK 18 에서 제거"라고
   적혀 있었는데, **그 18 은 이 저장소가 실행으로 확인한 적 없는 숫자**여서 이번에 그 문장도 함께 고쳤다.
3. **가상 스레드(JDK 21)는 이 랩에서 실행해 보지 않았다.** 9장의 스레드 풀 사이징
   전제를 바꾸는 큰 변화지만, JDK 17 기준 저장소라 **"책에 없다"고만 적고 검증하지 않았다.**
4. **10장의 Jakarta EE 전환은 패키지명 차원에서만 적었다.** 이 랩이 Spring Boot 3 을
   쓰므로 결과적으로 `jakarta.*` 위에서 돌고 있지만, **전환 자체를 검증한 케이스는 없다.**
5. **이 문서는 원서를 다시 읽어 만든 것이 아니라**, `notes/java-performance/` 의 요약
   13개를 기준으로 대조한 것이다. **요약 단계에서 빠진 내용은 여기서도 빠진다.**
