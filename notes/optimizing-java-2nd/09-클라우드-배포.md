# 9장 — 클라우드 배포 (Deploying to the Cloud)

> *Optimizing Cloud Native Java* 2판(2024) 9장 요약. **착수 순서 6순위**(클라우드 신규 장). 표기 — ✅ 실행해 확인 · 📄 문서로만 아는 것.
>
> **1판에 없던 신규 장.** 8장이 "무엇 위에 놓이는가"였다면 9장은 "어떻게 올리고 바꾸는가"다 — 로컬(Compose·Tilt) → 쿠버네티스(Deployment·Service·프로브) → 점진적 배포(블루/그린·Argo 카나리) → 기능 플래그. 성능 책답게 **배포 실수가 성능·가용성 사고로 이어진 사례**(Knight Capital)로 끝난다.

---

## 1. 이 장의 핵심 주장

1. **로컬 개발부터 컨테이너로**: Docker Compose 로 앱 + 의존 서비스(DB·브로커)를 한 파일로 띄우고, **Tilt** 로 코드 변경 → 이미지 재빌드 → 재배포를 자동화한다. "내 노트북에서는 됐는데"의 원인인 환경 차이를 없애는 것이 목적.
2. **쿠버네티스의 두 평면**: **컨트롤 플레인**(API 서버·etcd·스케줄러·컨트롤러 매니저) 과 **데이터 플레인**(노드의 kubelet·kube-proxy·컨테이너 런타임). 선언적 YAML 을 API 서버에 내면 컨트롤러가 현재 상태를 원하는 상태로 맞춘다.
3. **기본 객체**: `Deployment`(ReplicaSet 을 통해 Pod 수·롤링 업데이트 관리) → `Pod`(컨테이너 묶음, 가장 작은 배포 단위) → `Service`(안정적 가상 IP·DNS, ClusterIP/NodePort/LoadBalancer). Fighting Animals 의 Deployment·Service YAML 이 예제.
4. **사이드카와 서비스 메시**: 같은 Pod 안의 보조 컨테이너(로그 수집·프록시). **Istio** 는 Envoy 사이드카로 east-west 트래픽에 mTLS·재시도·관측을 얹는다 — 자바 코드를 안 바꾸고 붙지만 **홉마다 지연이 늘어난다**(10~12장의 관측 대상).
5. **프로브**: `livenessProbe`(죽었으면 재시작) 와 `readinessProbe`(준비 안 됐으면 트래픽 차단). **자바에 특히 중요** — JVM 기동·워밍업 동안 readiness 를 false 로 두지 않으면 콜드 JIT 상태의 인스턴스에 트래픽이 가서 지연 스파이크가 난다. MicroProfile Health / Spring Actuator 가 엔드포인트를 준다.
6. **이미지 태그 규율**: `imagePullPolicy` 와 **`:latest` 경고** — 어떤 이미지가 떴는지 알 수 없어 재현 불가. 다이제스트나 불변 태그를 써라.
7. **스케줄링 제어**: 노드 어피니티/안티어피니티·taint/toleration — 메모리 많은 노드에 JVM 을 두거나 같은 서비스 복제본을 다른 노드에 흩는다. **보안**: 루트가 아닌 사용자, 읽기 전용 파일시스템, 시크릿.
8. **원격 디버깅 "remocal"**: **Telepresence** 로 로컬 프로세스를 클러스터 서비스 자리에 끼워 넣어 클러스터 의존성을 그대로 쓰면서 로컬에서 디버깅한다.
9. **점진적 배포**: **블루/그린**(두 환경, 스위치 전환, 롤백 = 되돌리기) 과 **카나리**(일부 트래픽만 새 버전). **Argo Rollouts** 예제 — 20% 씩 단계를 올리며 `AnalysisTemplate` 으로 프로메테우스 메트릭(성공률·p99)을 자동 판정, 실패면 자동 롤백. 이것이 2장 "성능 테스트는 운영과 같은 환경에서" 의 클라우드 답이다.
10. **마이그레이션의 여섯 R**(Rehost·Replatform·Refactor·Repurchase·Retire·Retain) — 어느 길을 택했느냐가 이후 성능 작업의 범위를 정한다.
11. **기능 플래그**(LaunchDarkly 예): 배포와 릴리스를 분리한다. 단, 플래그 평가 비용과 플래그 누적(죽은 플래그) 이 부채다.
12. **Knight Capital(2012)**: 8대 중 7대에만 새 코드가 배포되고, 옛 플래그가 남은 1대에서 폐기된 코드 경로가 살아나 45분에 4.6억 달러 손실. 교훈 — **배포 자동화·일관성·죽은 코드 제거** 는 성능이 아니라 생존의 문제다.
13. **자바의 관심사**(8장과 이어짐): 컨테이너의 CPU/메모리 제한을 JVM 이 읽어 GC·힙·풀 크기를 정하므로 **K8s `resources.requests/limits` 가 곧 JVM 튜닝**이다. CPU limit 1 → SerialGC, 메모리 limit 1Gi → 힙 256Mi. `MaxRAM`·`MaxRAMPercentage`·`ActiveProcessorCount` 로 덮어쓴다.

## 2. 절별 상세 요약

- **9.1 Local development** — `docker compose up`, 서비스·볼륨·네트워크 정의, Tilt 의 `Tiltfile`(live_update).
- **9.2 Kubernetes** — 아키텍처 그림(컨트롤/데이터 플레인), `kubectl apply`, Deployment/Pod/Service YAML 전문, `type: LoadBalancer`, 롤링 업데이트 파라미터(`maxSurge`·`maxUnavailable`).
- **9.3 Sidecars and service meshes** — Istio 주입, mTLS, 트래픽 분할.
- **9.4 Health and readiness** — 프로브 YAML(`initialDelaySeconds`·`periodSeconds`·`failureThreshold`), 자바 워밍업과의 관계, startupProbe.
- **9.5 Image policy, affinity, security** — `imagePullPolicy: Always/IfNotPresent`, `:latest` 의 함정, nodeAffinity YAML, securityContext.
- **9.6 Debugging in the cluster** — Telepresence intercept, 포트포워딩, 8장 UBI-micro 이미지에 도구가 없을 때의 대안.
- **9.7 Deployment strategies** — 블루/그린 그림, Argo Rollouts `steps: setWeight 20 / pause / analysis` YAML, AnalysisTemplate 의 PromQL.
- **9.8 Migration and feature flags** — 여섯 R, LaunchDarkly SDK 코드, Knight Capital 사례.
- **9.9 Java concerns** — requests/limits ↔ JVM 에르고노믹스.

## 4. JDK 25 기준 평가

JVM 문장은 8장과 같은 "컨테이너 인식" 뿐이고 25 에서도 그대로다(CN-04A·04B·09A ✅, 8장 §4 표 참고). 25 에서 이 장에 더해 읽을 것 📄:

- **기동 시간**: readiness 를 늦추는 대신 **AOT 캐시**(JEP 483·514, 25)로 기동 자체를 줄일 수 있다. CN-06A ✅ 에서 캐시 적중 시 "shared objects file" 에서 읽은 클래스가 761 vs 기본 CDS 670 이었다 — 이 환경에서는 시간 차이를 유의미하게 재지 못했다(측정하지 않은 것을 적지 않는다).
- **카나리 판정 메트릭**: Argo AnalysisTemplate 이 보는 p99 는 11장의 Micrometer 히스토그램에서 나온다(CN-10A: 백분위수는 평균 낼 수 없다 ✅).
- **가상 스레드**(21 정식, 25 에서 동기화 고정 해소 JEP 491 ✅ CN-13A) — "CPU 1개 컨테이너에서 처리량" 이야기와 맞물린다. 13장.

## 6. 면접에서 쓸 수 있는 문장

- "readinessProbe 는 JVM 에 특히 중요합니다. JIT 워밍업 전에 트래픽이 들어오면 첫 수천 요청이 인터프리터로 돌아 p99 가 튀니까요. 기동 직후 워밍업 요청을 돌리고 그 뒤 ready 를 올립니다."
- "쿠버네티스 limits 가 곧 JVM 튜닝입니다. CPU 1 이면 SerialGC, 메모리 1Gi 면 힙 256Mi 로 뜹니다. `MaxRAMPercentage` 로 힙 비율을 올리되 메타스페이스·스레드 스택·코드 캐시 몫을 남겨야 OOMKilled 를 피합니다."
- "`:latest` 태그는 어느 코드가 떴는지 모르게 만듭니다. 성능 회귀를 추적하려면 다이제스트로 고정해야 합니다."
