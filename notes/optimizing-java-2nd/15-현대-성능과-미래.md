## 1. 이 장의 핵심 주장

1. **새 동시성 패턴** — 가상 스레드에서 이어지는 두 API. **구조적 동시성**(JEP 453): 협력하는 서브태스크(보통 가상 스레드)를 **하나의 단위로** 관리. 흐름 — 스코프 생성(소유 스레드) → `fork()` → `join()`(전부 끝날 때까지) → 오류 처리·결과 → 스코프 닫기(try-with-resources). 21 에서 `fork()` 는 `Future` 가 아니라 **`Subtask`**(Supplier, 검사 예외 없음)를 돌려준다 — join 뒤에만 읽기 때문. 정책 — **`ShutdownOnFailure`**(하나 실패 → 전부 취소; `StockTip` 예제, `throwIfFailed()`) · **`ShutdownOnSuccess`**(첫 성공 → 나머지 취소; `race()` 예제, `joinUntil(deadline)`). 서브태스크가 서브스코프를 만들면 **트리**. 부수효과만이면 `StructuredTaskScope<Void>`(서버 소켓 예제) — 하지만 그건 `newVirtualThreadPerTaskExecutor()` 의 fire-and-forget 이 나을 때가 많다. **데이터 병렬(암달)이 아니라 태스크 병렬(I/O)** 용. "어느 스레드를 가상으로 바꿀지 100% 판정하는 도구는 없다 — 사람의 일".
2. **ScopedValue**(JEP 446): `java.lang.ScopedValue<T>` — 스코프 안에서 **한 번 쓰고 불변**, 호출 체인 어디서나 `get()`, 스코프 밖에서는 없다. **ThreadLocal 의 현대적 대안** — `set()` 이 없어 멀리서 못 바꾸고, 런타임 최적화 여지. 목표 — 스레드·자식 스레드와 공유, 제한된 수명, 코드 구조에서 보이는 수명, 불변이라 많은 스레드가 공유. 패턴 — `static final` 홀더 · `ScopedValue.where(SV, v).run(() -> ...)` · 람다가 스코프 본문. **동적 스코프**(셸·Lisp·Perl 식) vs 자바의 어휘 스코프. 구조적 동시성과 결합 — 서브스코프에서 **재바인딩**(권한 강등 예제 `SecurityLevel.ADMIN → USER`), 재바인딩 안 한 값은 상속. 컨티뉴에이션 등 저수준 부품은 `jdk.internal.vm` 에 있어 쓰지 말 것.
3. **Panama**: JVM ↔ 네이티브. **FFM API** — 19 미리보기 → 22 정식(LTS 아님이라 여기서 다룬다). 목표 — 생산성(JNI 대체) · 성능(JNI/Unsafe 이상) · 플랫폼 · 균일성(네이티브·영속·힙 메모리) · **건전성(use-after-free 없음)** · **무결성(안전하지 않은 연산은 기본 경고)**. 핵심 개념 **`Arena`**(수명; confined/shared/global/automatic) 와 **`MemorySegment`**(`allocate(long)` — ByteBuffer 의 2 GB 한계 없음; 16 GiB 예제). **Vector API 는 Valhalla 의 기능이 미리보기가 될 때까지 인큐베이션** — 더 멀고 더 투기적.
4. **Leyden**: 목표 "기동 시간·피크 도달 시간·풋프린트 개선" — "번개를 병에 담기"(HotSpot 의 동적 추론을 **기동 전으로 옮긴다**). C++ 은 정적을 택해 동성을 버리고 Python 은 동적을 택해 정적을 못 붙이는데, HotSpot 은 **동적 상태를 투기적으로 정적으로 바꾼다** — Leyden 은 그 시점을 앞당긴다. **"AOT 컴파일 제공"보다 일반적** — 결과와 메커니즘의 구분(6장). GraalVM·Quarkus 경험을 표준화. 두 메커니즘 —
   - **컨덴서와 정적 런타임 이미지**: **폐쇄 세계 제약**(외부 클래스 로드 불가, 동적 클래스 생성 불가)은 너무 강해 **점진적** — 더 약한 제약의 중간 상태를 탐색. **계산 이동**(상수 접기·CDS = 앞으로, 지연 로딩·GC = 뒤로). 컨덴서 = 의미 보존 전체 프로그램 변환(새 코드·데이터·메타데이터·제약), **합성 가능**. 충분히 강한 컨덴서를 쌓으면 정적 네이티브 이미지가 **창발적으로** 나온다. 2024-08 시점 메인라인에 거의 없음(indy 링크 컴파일 시 해석, 지연 계산 `static final`).
   - **Premain**: 워밍업(95% 처리량 도달)을 줄인다. **CDS → AppCDS → 동적 AppCDS(17, `-XX:SharedArchiveFile`)** 위에서 **훈련 실행**으로 상태·프로파일·JIT 코드를 아카이브 → **배포 실행**에서 재사용. 기동의 심볼 해석·`<clinit>`·indy BSM 을 훈련에서 미리. **C1 코드**(비투기적, 역최적화 없음)를 인터프리터 대신 쓰고, C2 코드도 프로파일에서 재생성. 훈련 = "동적으로 태어났지만 정적처럼 보이는" 데이터 + **역최적화 탈출구** — 이것이 **완전 AOT(Native Image)보다 나은 이유**: 금융의 "특이한 날"(NFP·옵션 만기)에 완전 AOT 는 훈련 가정을 못 되돌린다. 향후 자동 훈련·사용자 정의 활동(순수성 주석).
5. **Valhalla**(2014~): 목표 — 메모리 배치를 하드웨어 비용 모델에 맞춤 · 원시 타입까지 제네릭 · 라이브러리의 호환 진화. **"1판의 설명은 이제 완전히 틀렸다"**(경고). 참조 배열 vs 구조체 배열(`Point3D` 그림 15-1~15-4) — 캐시 지역성 + 헤더 비용 절약, Panama 로 GPU 오프로드 가능성. 최상위 타입 부재 → `List<int>` 불가(타입 소거 탓이 아니다). 현재 설계 — **"클래스처럼 코딩하고 int 처럼 동작"**, 키워드 **`value`** 하나, 기존 클래스는 **identity 클래스**. **새 바이트코드 없음**; 큰 변화는 **`if_acmpeq`** — 값 객체 비교는 필드 재귀 비교(`VR0 → VR1 → … → VRN`), 임의 깊이 재귀 가능성 → 성능 우려; 순환 필드 금지. C2 는 할당 회피·"고급 박싱". **Valhalla 를 안 켠 기존 코드에 회귀가 없어야** 한다. "어느 릴리스인지 불명"(2024-08).
6. **결론**: 1판에서 아직 유효한 것을 이어 오고 클라우드 기법을 더했다. JVM 실행 모델·GC 의 숙련만으로는 부족하고 **오케스트레이션·관측가능성이 일상**이 됐다. 근본은 안 바뀌었다 — 층이 늘었을 뿐.

## 2. 절별 상세 요약

- **New Concurrency Patterns** — 구조적 동시성 6단계, `Subtask` vs `Future` 의 이유, 세 예제(`StockTip`·`race`·`runAll`), `serveScope` 의 `<Void>`, 두 정책, `shutdown()`·`joinUntil()`.
- **Scoped Values** — 목표 5개, `ServerSV` 예제, 패턴 4개, 재바인딩 예제(`securitySV`·`requestSV`).
- **Panama** — 목표 6개, `Arena`/`MemorySegment` 예제, 아레나 종류, Vector API 보류 이유. (책은 "21 에서는 `jdk.incubator.foreign` 패키지"라고 적었는데 **21 에서는 이미 `java.lang.foreign` 의 미리보기**였다 — 인큐베이터 모듈은 17~18 이야기. 이 환경의 21 에서 `java.lang.foreign.Linker` 가 미리보기 API 로 존재했다 ✅)
- **Leyden** — 이름의 유래(라이덴 병·콘덴서), 이미지·제약·컨덴서, 계산 이동의 예, premain 과 훈련/배포 실행, C1 코드 재사용, "특이한 날" 논증.
- **Valhalla** — 목표, 경고, 그림, `value record` 예제와 `==` 출력(false/true/false), C2 영향, 무회귀 원칙.

## 4. JDK 25 기준 평가 — 실행으로 확인한 것

| 책의 문장 | JDK 25 실행 | 상태 |
|---|---|---|
| `ScopedValue` 는 미리보기 | **정식.** `where(...).run()` 안에서 `get()` 됨, 중첩 재바인딩 후 복원, **밖에서 `get()` 은 `NoSuchElementException`**, `Thread.ofVirtual` 로 만든 자식 스레드에는 상속되지 않는다(구조적 동시성 스코프 안에서만 상속) | ✅ CN-13C |
| `StructuredTaskScope` 는 미리보기 | **아직 미리보기** — 25 는 `StructuredTaskScope.open()` 팩토리·`Joiner` 로 API 가 바뀌었다(책의 `new ShutdownOnFailure()` 는 컴파일되지 않는다). `--enable-preview` 없이는 못 쓴다 | ✅ |
| FFM 으로 네이티브 호출 | `Linker.nativeLinker().downcallHandle(strlen)` 동작. `--enable-native-access=ALL-UNNAMED` 없으면 **"restricted method" 경고**(JEP 472 의 무결성 기본값). 21 에서는 미리보기 | ✅ CN-15B |
| Leyden 은 조기 단계 | **AOT 캐시 정식** — `-XX:AOTCacheOutput=app.aot`(한 단계, JEP 514) 와 `-XX:AOTMode=record/create` 둘 다 동작. "shared objects file" 에서 읽은 클래스 수: 캐시 사용 시 761 vs 기본 CDS 670 vs `-Xshare:off` 0. **클래스패스가 디렉터리면 거부**("Cannot have non-empty directory in paths") — JAR 이어야 한다. 21 은 `AOTCache` 옵션 자체를 모른다 | ✅ CN-06A |
| 동적 AppCDS(17, `SharedArchiveFile`) | 그대로. AOT 캐시가 그 상위 호환 | 📄 |
| 가상 스레드의 `synchronized` 고정(13장) | **25 에서 해소(JEP 491)** — 캐리어 1개·`synchronized` 안 블로킹 실험이 21 에서 607 ms, 25 에서 10 ms | ✅ CN-13A |
| 컴팩트 객체 헤더(4·5장) | 25 정식(JEP 519), 기본 꺼짐, 켜면 빈 객체 16 → 8 바이트 | ✅ CN-05C |
| Vector API | 25 도 인큐베이터(`jdk.incubator.vector`) — 실행하지 않았다 | 📄 |
| Valhalla | 25 에 없음 — 실행할 것이 없다 | 📄 |
| Unsafe 메모리 접근 | `allocateMemory` 호출 시 경고, `--sun-misc-unsafe-memory-access=deny` → `UnsupportedOperationException`. 21 은 그 옵션이 없다 | ✅ CN-15A |

## 6. 면접에서 쓸 수 있는 문장

- "ScopedValue 는 ThreadLocal 과 달리 스코프 안에서 한 번 바인딩되고 불변입니다. JDK 25 에서 정식이 됐고, 구조적 동시성 스코프 안에서만 자식 스레드에 상속됩니다."
- "Leyden 의 AOT 캐시는 훈련 실행으로 클래스 로딩·링크·프로파일을 아카이브해 기동을 줄입니다. 완전 AOT 와 달리 역최적화 탈출구가 남아서, 훈련 때 못 본 경로가 와도 HotSpot 이 다시 컴파일합니다."
- "구조적 동시성은 25 에도 미리보기입니다. 운영 코드에는 아직 `newVirtualThreadPerTaskExecutor` 와 명시적 join 이 정답입니다."
