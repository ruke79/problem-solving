# 5장 — 고급 가비지 컬렉션 (Advanced Garbage Collection)

> *Optimizing Cloud Native Java* 2판(2024) 5장 요약. **착수 순서 4순위**(GC). 책의 기준은 **JDK 21 — 세대형 ZGC 가 막 들어온 시점**이다.
> 표기 — ✅ 실행해 확인(JDK 17.0.19 / 21.0.10 / 25.0.4) · 📄 문서로만 아는 것.
>
> **1판 7장 「고급 GC」의 개정판.** 1판이 CMS 를 현역(65회)으로 다룬 반면 2판은 **"틈새 수집기" 절의 역사 노트**(16회)로 내렸고, ZGC 절이 1회 언급에서 **39회의 정식 절**로 커졌다.
> 1판 검토 §7 의 보정 제안("CMS 절을 동시 수집기 일반으로, ZGC 보충")은 2판이 그대로 수행한 셈이다.
>
> **JDK 25 기준 이 장의 변화 한눈에** — 이 장이 2판에서 **가장 많이 낡은 장**이다.
>
> | 책의 서술 (JDK 21) | 지금 (JDK 25) | 근거 |
> |---|---|---|

> | 세이프포인트 폴 ("스레드 로컬 핸드셰이크로 그림이 조금 바뀌었다") | 그대로. `ThreadLocalHandshakes` 플래그는 17 부터 없다(항상 켜짐) | ✅ |

## 1. 이 장의 핵심 주장

1. GC 는 **플러거블**이고 만능 알고리즘은 없다. 관심사: **STW 일시정지 길이 · 처리량(GC 시간 비율) · 일시정지 빈도 · 회수 효율 · 일시정지 일관성.** 일시정지 길이에만 매달리지 마라 — 배치는 처리량이 전부고, "GC 시간 비율이 낮다"는 앱이 일을 못 해 가비지가 적은 것일 수도 있다. **압축**은 캐시 지역성으로 앱을 빠르게 하므로 GC 시간을 조금 더 써도 남는 장사일 수 있다 — 재라.
2. **동시 GC 이론**: 비결정성은 할당에서 온다(Dijkstra). **세이프포인트** — JVM 은 스레드를 강제로 세울 수 없고 세이프포인트에서 나가는 것만 막을 수 있다. 전역 플래그 → 폴 → 대기. 폴 위치: 인터프리터는 바이트코드 사이, JIT 코드는 메서드 종료·루프 백브랜치. 모니터 블로킹·JNI 실행 중이면 자동으로 세이프포인트. **트라이컬러 마킹**(Dijkstra·Lamport 1978): 회색/흰색/검은색, **SATB**, 트라이컬러 불변식(검은색→흰색 참조 금지)과 뮤테이터가 깨뜨리는 경우 → 쓰기 장벽으로 회색 되돌리기(단조성 상실) 또는 큐 + **STW 리마크**(G1 의 선택). **포워딩(Brooks) 포인터**: 객체당 한 워드(Integer 20→28바이트), CAS 로 갱신 — 초기 Shenandoah.
3. **G1**: 6 실험 → 8u40 안정 → 9 기본. CMS 대체용 저지연 수집기로 시작해 범용이 됐다. **일시정지 목표**(`MaxGCPauseMillis=200`, 보장 아님). **리전**(1~512MB 2의 제곱, 힙/2048, 2,048~4,095개), **거대(humongous) 객체**(리전 절반 초과 → 연속 리전에 직접, 올드 소속). **영 GC(G1New)** 는 STW 퇴거, **혼합 GC(G1Old)** 는 대부분 동시 — **IHOP**(45%, 적응형)에서 시작, 네 단계(Concurrent Start[STW+영 GC] → Concurrent Mark → Remark[STW] → Cleanup[STW]). `ConcGCThreads = max(1, (ParallelGCThreads+2)/4)` — 혼합 중 앱 처리량이 줄고 그때의 영 GC 는 더 오래 걸린다. **RSet**(리전별 유입 참조; 플로팅 가비지 원인, Cleanup 에서 스크러빙). **풀 GC** 원인: 거대 리전 단편화, **동시 모드 실패**(마킹이 할당을 못 따라감) → IHOP 낮추기(`G1ReservePercent` ↑, `-G1UseAdaptiveIHOP` + `InitiatingHeapOccupancyPercent`), `G1HeapRegionSize=<n>m`(m 필수). "컨테이너에 코어가 하나면 G1 은 동시 실행이 불가능해 Serial 로 떨어진다."
4. **Shenandoah**(Red Hat, 12 실험 → 15 정식 → 17·21 완전 지원, 8·11 백포트): 대형 힙(수십~수백 GB)의 일시정지를 **동시 압축**으로 낮춘다, CPU 를 더 쓴다. 9단계(Init Mark[STW] → Concurrent Mark → Final Mark[STW] → Concurrent Cleanup → Concurrent Evacuation → Init Update Refs[STW] → Concurrent Update Refs → Final Update Refs[STW] → Concurrent Cleanup). 동시 퇴거 = TLAB 에 추측 복사 → CAS 로 포워딩 갱신 → 진 스레드는 되돌림. 진화: 13 의 **로드 참조 장벽**으로 Brooks 워드 제거(마크 워드 비트로 "포워딩됨" 표시), 14 자가 수정 장벽·동시 클래스 언로딩, 15 동시 참조 처리, 17 동시 스레드 스택 처리. **"아직 세대형이 아니다"** → §4.
5. **ZGC**(Oracle, 11 실험 Linux/x64 → 17·21 정식): 힙·메타스페이스 크기에 비례하는 모든 작업을 세이프포인트 밖으로 — **1ms 이하 일시정지, 16TB 까지**. 동시·리전·압축·NUMA 인식·**색칠 포인터**(메타데이터를 포인터 비트에; 압축 oop 없음, 44비트 주소)·**로드 장벽**. 멀티매핑 때문에 RSS 가 최대 3배 과대 보고(PSS 를 봐라). 튜닝 없음이 목표(IHOP 대신 비용 모델, 동적 스레드 수). **세대형 ZGC(21, JEP 439)**: minor/major, 색 비트 4 → 12, 스택의 무색 포인터를 변환, 멀티매핑 대신 장벽 코드. `-XX:+UseZGC -XX:+ZGenerational`, "비세대형을 완전히 대체할 의도".
6. **Balanced(Eclipse OpenJ9)**: 리전(512KB 부터, 최대 2,048개), 리전 나이, **PGC**(부분 GC, Eden + 선택한 나이 리전, STW), **GMP**(전역 마크, 부분 동시, 플로팅 가비지 상한), **GGC**(전역 STW 압축). 클래스 로더의 증분 언로딩. 객체 헤더는 클래스 슬롯 하나(64/32비트, 압축 참조는 57GB 미만 기본) + 필요 시 모니터/해시 슬롯(정렬 빈틈에). **arraylet**(스파인 + 리프, JNI 에서 보일 수 있음). NUMA 인식 배치.
7. **틈새**: **CMS** — 테뉴어드 전용 저지연, ParNew 와 짝, 9 폐기·14 제거. 8 에서는 아직 G1 보다 나은 워크로드가 있었으나 11 에서 드물다. 동시 모드 실패 → ParallelOld 폴백. **Epsilon**(JEP 318) — 아무것도 회수하지 않는 실험용, JMH·회귀·무할당 코드 테스트용, **운영 금지**.

## 2. 절별 상세 요약

(§1 이 이미 절 순서대로 상세하므로 보충만 적는다.)

- **트레이드오프 절**: Lego Mindstorms 처럼 GC 없는 자바 구현도 있었다. "Oracle/OpenJDK 21 기준 수집기 넷".
- **세이프포인트 절**: JVM 은 "완전한 선점형이 아니다"(공공연한 비밀). 빨리 멈춘 스레드는 느린 스레드를 기다리고 그 시간은 일시정지 통계에 다 안 잡힐 수 있다. `CountDownLatch` 비유.
- **G1 리마크 각주**: 2024-08 현재 리마크의 잠재적 시간 낭비는 약한 참조 처리(무제한 마킹 가능).
- **Shenandoah 그림 5-7**: Shipilëv 의 일시정지 비교 그래프. Oracle 은 Shenandoah 를 싣지 않고 다른 OpenJDK 빌드는 싣는다(각주).
- **ZGC 각주**: JEP 439 참조. 제거 절차 3단계(폐기 → 제거 예정 폐기 → 제거) 각주.
- **Balanced**: IBM 출신, 4GB 초과 힙 대상. 압축 참조 기본 경계 57GB(HotSpot 은 32GB).

## 4. JDK 25 기준 평가

배너 표의 근거를 풀어 쓴다 — **세 수집기 모두 "세대형"이 된 것**이 핵심이다.

- **ZGC**: 21 의 `-XX:+UseZGC` 는 `[ZGC Cycles][ZGC Pauses]`(비세대형), `+ZGenerational` 은 Minor/Major ✅. 25 는 플래그와 무관하게 Minor/Major 이고 `-XX:-ZGenerational` 로 돌아갈 수 없다 ✅. 책의 "현재 사용자는 세대형으로 옮겨라"는 25 에서는 선택이 아니라 사실이다. 멀티매핑 관련 RSS 과대 보고 서술은 비세대형 이야기였으므로 **25 에는 해당 없음** 📄.
- **Shenandoah**: 25 에서 `ShenandoahGCMode=generational` 기동 + `[gc,init] Mode: Generational` ✅, 21 은 `Unknown -XX:ShenandoahGCMode option` ✅. JEP 404 는 24 에 실험으로, **JEP 521 이 25 에 정식**으로 실었다 📄. 기본은 `satb`(단일 세대) ✅ — 세대형은 옵트인이다. GC 빈 이름은 모드와 무관하게 `[Shenandoah Pauses][Shenandoah Cycles]` ✅.
- **G1**: 25 에 25 자체의 JEP 는 없지만 리전 피닝(JEP 423, 22) 📄, 쓰기 장벽 단순화(JDK 25 JEP 없음 — 확인하지 않음). 이 머신 25 의 에르고노믹: `G1HeapRegionSize=2097152`(3.4GB 힙 ÷ 2048 → 1.6MB → 2MB 로 올림) ✅ — 책의 공식과 맞다(책은 "내림"이라 썼는데 이 관측은 올림이다 — 공식의 방향은 확인이 더 필요하다 📄). `MaxGCPauseMillis=200` ✅, `G1PeriodicGCInterval=0` ✅.
- **컴팩트 객체 헤더**(JEP 519): 이 장의 "ZGC 는 압축 oop 없음" 과 별개로 헤더 자체가 8바이트가 될 수 있다 ✅ CN-05C.
- **Epsilon**: 25 에도 `-XX:+UnlockExperimentalVMOptions -XX:+UseEpsilonGC` 로 있다(이 세션 앞부분에서 17 확인 ✅, 25 는 📄).
- **Balanced/OpenJ9**: 이 저장소에 OpenJ9 가 없어 확인하지 않았다 📄.

## 6. 면접에서 쓸 수 있는 문장

- "JDK 21 까지는 ZGC 가 비세대형이 기본이고 `ZGenerational` 로 세대형을 켰지만, 23 에서 세대형이 기본이 되고 24 에서 비세대형이 제거됐습니다. 25 에는 세대형 ZGC 만 있습니다."
- "Shenandoah 도 25 에서 세대형 모드가 정식이 됐습니다. 기본은 아직 단일 세대(satb)라 `ShenandoahGCMode=generational` 로 켭니다. 이제 G1·ZGC·Shenandoah 셋 다 세대형이 있습니다."
- "G1 의 혼합 GC 는 대부분 동시지만 코어의 일부를 쓰므로 그동안 앱 처리량이 떨어지고, 그때 오는 영 GC 는 더 오래 걸립니다. 컨테이너에 코어가 하나면 동시 실행 자체가 안 돼 Serial 로 떨어집니다."
- "동시 수집기의 적은 할당률입니다. 마킹이 할당을 못 따라가면 동시 모드 실패로 풀 GC 가 옵니다. G1 은 IHOP 을 적응적으로 낮추고, ZGC 는 비용 모델로 시작 시점을 정합니다."
