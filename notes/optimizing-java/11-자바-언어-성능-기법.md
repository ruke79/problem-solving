## 1. 이 장의 핵심 주장

1. 외부 요인(네트워크·I/O·DB) 다음의 병목은 **코드 설계**, 특히 **데이터를 어떻게 담는가**다. 직접 정렬을 짜기 전에 `Collections` 를 봐라.
2. 자바 컬렉션에는 **객체가 아니라 참조**가 들어간다 — C 의 구조체 배열이 없다(Gil Tene: "자바와 C 사이의 마지막 큰 성능 장벽"). ObjectLayout 프로젝트, 15장의 **값 타입**(Valhalla)이 해법 후보.
3. **`ArrayList`**: 첫 add 에 용량 10, 꽉 차면 새 배열 복사. **용량을 미리 줘라**(JMH 287 vs 190 ops/s). **`LinkedList`**: 앞 삽입 O(1)(560 vs 3.4 ops/ms) 이지만 인덱스 접근은 참담(0.86 vs 269,569 ops/ms). **기본은 `ArrayList`**. `Vector`·`Stack` 은 쓰지 마라.
4. **`HashMap`**: 버킷 16·로드 팩터 0.75, 상위 비트를 섞는 스프레딩(Shannon 의 엄격한 눈사태 기준), **트리화(TREEIFY_THRESHOLD)** — 버킷이 커지면 `TreeNode`(2배 크기)로; 트리화가 자주 보이면 해시 함수·초기 용량을 다시 봐라. 초기 용량 = 최대 원소 수 / 로드 팩터. `LinkedHashMap` 은 드물게, `TreeMap` 은 범위 질의(log n). MultiMap 은 없다(`Map<K, List<V>>`).
5. **도메인 객체는 탄광의 카나리아** — `jmap -histo` 상위 30 에 도메인 객체가 보이면 누수 후보. **모든 세대 효과**(생존 횟수 히스토그램에 전 세대에 걸쳐 나타남). 짧은 수명 도메인 객체는 SATB 의 플로팅 가비지. 긴 마크 시간의 범인일 수 있다.
6. **파이널라이즈는 쓰지 마라** — RAII 처럼 보이지만 GC 가 언제 돌지 모르니 자원 해제 시점을 보장하지 못한다(TCP 커넥션 누수 실화: 타임아웃 경로에 `close()` 가 없어 파일 핸들 고갈).
   구현은 `return_register_finalizer` 사설 바이트코드 → 파이널라이즈 큐 → 별도 스레드 → **다음 GC 사이클에서야 회수**(최소 한 사이클 더 산다, 예외는 무시된다). Java 9 에서 `Object.finalize()` 폐기. **`try-with-resources`** 가 답 — 순수 컴파일 타임 설탕(바이트코드 비교 수록), 유일한 성능 영향은 생성 바이트코드가 늘어 인라이닝에 영향을 줄 수 있다는 것.
7. **메서드 핸들** — `invokedynamic` 의 BSM 이 돌려주는 콜 타깃. `Lookup` 컨텍스트가 `setAccessible()` 을 대체하고, **시그니처 다형성**으로 `invoke:(Ljava/lang/String;)I` 처럼 정적 타입이 바이트코드에 남는다.

## 2. 절별 상세 요약

### 2-1. 컬렉션 최적화
- 순차 컨테이너 vs 연관 컨테이너, `hashCode()`/`equals()` 계약(Effective Java).
- **리스트**: 표의 세 JMH(용량 지정 / 앞 삽입 / 인덱스 접근). "예시용이지 권위 있는 수치가 아니다." 동기화는 `Collections.synchronizedList()`(데코레이터) 또는 12장의 동시 컬렉션.
- **맵**: 단순화한 `HashMap.get()`/`indexFor()`/`Node` 코드. 리해시 = 버킷 2배 + 재분배. 반복 비용은 용량·로드 팩터에 좌우. 트리화 설명. `LinkedHashMap`(삽입/접근 순서), `TreeMap`(레드-블랙, 서브맵, 스트림 분할 처리에 유리).
- **집합**: `HashSet` 은 `HashMap<E, PRESENT>` 위에(코드 수록), `LinkedHashSet` 은 보호 생성자로 `LinkedHashMap`, `TreeSet` 은 `TreeMap` 위에.

### 2-2. 도메인 객체
`Order`/`OrderItem`/`DeliverySchedule` 예제. 힙의 흔한 상위 항목은 문자열·`char[]`·`byte[]`·컬렉션이므로 **도메인 타입이 상위에 있으면 이상 신호**(결정적이진 않다). 작업 집합 크기가 기대 범위인지 보는 것이 빠른 승리.

### 2-3. 파이널라이즈 회피
C++ RAII `file` 클래스 예. 실화. `finalize()` JavaDoc. 등록 경로(`c1_Runtime.cpp` 의 `register_finalizer_id`), 3단계 확장 생애주기, `java.lang.ref.Finalizer`(`static void register(Object finalizee) { new Finalizer(finalizee); }` — 부작용만을 위한 `new`), `FinalReference`. Java 7 이전 `readFirstLineOld` vs `readFirstLineNew` 의 `javap` 비교(예외 테이블, `addSuppressed`). 결론: 파이널라이즈는 목적에 부적합, `finalize()` 를 덮어쓴 클래스는 리팩터링하라.

### 2-4. 메서드 핸들
리플렉션 `Method.invoke` 바이트코드(가변 인자 배열 박싱) vs `MethodHandles.lookup().findVirtual(String.class, "hashCode", methodType(int.class))` + `(int) mh.invoke("b")`. 로드 시점 접근 검사 후에는 검사가 없다는 리플렉션의 창. `Lookup` 은 불변 컨텍스트라 캐시·선택적 공개 패턴이 가능. C# dynamic 과 비슷한 "언어·프레임워크 구현자용" 기능.

## 3. §7 의 보충 — Compact Strings (책에 없는 것)

이 장은 문자열을 "가장 흔한 힙 객체"로만 다루고 **JDK 9 의 Compact Strings(JEP 254)** 를 모른다(1판 15장이 `byte[] value`/`coder` 를 소스로 보여 주긴 한다 — §0 검토 정정표).

- 표현: `char[]`(문자당 2바이트) → **`byte[]` + `coder`**(LATIN1=0: 1바이트/문자, UTF16=1: 2바이트/문자). ✅ 17·21·25 모두 `String` 의 인스턴스 필드는 `byte[] value`, `byte coder`, `int hash`, `boolean hashIsZero`.
- 플래그 `-XX:+CompactStrings` 기본 `true` ✅ 17·21·25.
- 실측(이 세션, JDK 17): **ASCII 10자 = 10 바이트, 한글 5자 = 10 바이트** — `value.length` 기준 ✅. 즉 라틴-1 만이면 메모리가 절반, 한 글자라도 비라틴이면 전체가 UTF-16.
- 이 장의 히스토그램 이야기에 미치는 영향: `jmap -histo` 에서 `[C`(char 배열)가 아니라 **`[B`(byte 배열)** 가 문자열 뒤에 온다 — 2판 12장도 이 점을 고쳐 적었다.
- 실행 근거: **`verify-labs-perfbook` PERF-11E**(§7 제안 → 이번에 추가) — 스레드 할당 바이트로 ASCII 문자열과 같은 길이의 한글 문자열의 할당량을 비교한다.

## 5. JDK 17 / 25 기준 — 어긋나는 것

| 책의 서술 | 지금 | 근거 |
|---|---|---|
| `Object.finalize()` 는 Java 9 에서 폐기 | **JDK 18(JEP 421)부터 제거 예정 폐기** — 17: `since=9 forRemoval=false`, **21·25: `since=9 forRemoval=true`**. 25 에도 아직 있다 | ✅ 리플렉션 |
| 파이널라이즈를 쓰지 마라 | 더 강해졌다. `--finalization=disabled` 로 아예 끌 수 있다(JDK 18+) | 📄 |
| 문자열은 `char[]` 를 참조 | **`byte[]` + `coder`**(Compact Strings) | ✅ §3 |
| `HashMap` 기본 16 / 0.75 / 트리화 | 그대로 | 📄 (소스 미확인, 동작은 java-tutorial 레슨에서 다룸) |
| 값 타입은 15장의 미래 | **JDK 25 에도 미출하**(Valhalla JEP 401 프리뷰 미포함) | 📄 |
| 리플렉션과 메서드 핸들은 별개 | JDK 18 부터 **리플렉션이 메서드 핸들 위에** 구현(JEP 416) | 📄 |
| `jmap -histo` | 그대로 있다 | ✅ 17·21·25 `jmap` 존재 |

## 7. 면접에서 쓸 수 있는 문장

- "`finalize()` 는 GC 가 언제 돌지 모르니 자원 해제 시점을 보장하지 못하고, 파이널라이즈 대상은 최소 한 GC 사이클을 더 삽니다. JDK 18 부터는 제거 예정 폐기라 `try-with-resources` 로 바꿔야 합니다."
- "JDK 9 부터 `String` 은 `char[]` 가 아니라 `byte[]` 에 coder 를 둡니다. 라틴-1 만이면 문자당 1바이트, 한글이 하나라도 섞이면 전체가 2바이트입니다."
- "`HashMap` 버킷이 길어지면 트리로 바뀌는데, 그게 자주 보이면 해시 함수나 초기 용량을 의심합니다."
