# 13장 — 프로파일링 (Profiling)

> *Optimizing Java* 1판(2018) 13장 요약. [`00-검토-2018년-책과-현재.md`](00-검토-2018년-책과-현재.md) §7 의 **착수 순서 6순위**(8·13장 — 보정이 많다). 표기 — ✅ 실행해 확인 · 📄 문서로만 아는 것.
>
> ⚠️ **도구 절반이 바뀌었다.** 책의 hprof 는 JDK 9 에서 제거됐고, Censum·Illuminate(jClarity)·Thermostat 은 사라졌으며, JFR/JMC 는 **상용 → 오픈소스**가 됐다. §7 제안대로 **"Censum/hprof → 현재 도구"** 로 보정했다(§4). 원리 부분(세이프포인트 편향·샘플링·할당 프로파일링)은 그대로 맞다.
>
> **2판(2024)에서는** [12장 「프로파일링」](../optimizing-java-2nd/12-프로파일링.md) — 같은 뼈대에 Async Profiler 중심, JFR 상세, 컨테이너 안 프로파일링이 더해졌다.

## 1. 이 장의 핵심 주장

1. **프로파일링은 두 종류** — **실행**(어느 코드가 CPU 를 쓰나) 과 **할당**(어느 코드가 메모리를 만드나). **프로파일러는 앱 동작을 왜곡하고 편향을 보인다** — 도구 여러 개로 대조하고, 자신의 인지 편향(보고 싶은 것을 찾는)도 경계하라(4장 안티패턴).
2. **모니터링 · 알림 · 프로파일러**를 구분한다. 프로파일러는 에이전트(시작 시 또는 동적 부착)로 붙는 **개발자 도구**.
3. **프로파일링 전에 문제가 있어야 한다**(Knuth — "임계 코드를 잘 보라, 단 그 코드가 식별된 **뒤에**"). 조건: **CPU ~100% 유저 모드**. 아니면 프로파일러 출력에 심하게 오도된다("도구는 늘 숫자를 내놓는다"). 유저 100% 여도 **GC STW 를 먼저 배제** — GC 로그가 바쁘면 GC 튜닝이 다음 단계이지 실행 프로파일링이 아니다.
4. **샘플링과 세이프포인트 편향**: 모든 진입·이탈을 기록하면 비용이 커서 **스택 샘플**을 뜬다(New Relic 100ms). 그런데 대부분의 프로파일러는 **세이프포인트에서만** 샘플을 뜬다 → ① 모든 스레드가 세이프포인트에 도달해야 하고(`GetCallTrace()` — 스레드 N 개면 N 번 세이프포인트) ② **세이프포인트에 있는 상태만 보인다.** `-XX:+PrintGCApplicationStoppedTime` 으로 세이프포인트 시간을 로그에. 예 — **카운티드 루프**: 큰 루프는 백엣지마다 세이프포인트 검사가 있지만 작은 루프는 **언롤링되어 루프가 끝날 때까지 세이프포인트가 없다** → 그 코드 덩어리에는 샘플이 **한 번도** 안 찍힌다. Kirk Pepperdine — "프로파일러를 쓸 때쯤이면 세부를 채워야지, 놀라게 해서는 안 된다."
5. **개발자용 실행 프로파일러**: **VisualVM**(무료, 단순, 곧 넘어선다) · **JProfiler**(상용, `-agentpath`, GUI 연결 대기, 헤드리스 스냅샷, 원격 마법사) · **YourKit**(상용, `libyjpagent.so`, 부착 모드 가끔 GUI 멈춤) — **둘 다 세이프포인트 샘플링**이라 같은 편향. 책의 스크린샷은 CPU 바운드가 아닌 GUI 앱이라 **시연용일 뿐**이라고 스스로 밝힌다.
6. **JFR / JMC**: BEA JRockit 에서 온 도구. **Java 8 기준 상용·사유** — Oracle JDK 만, `-XX:+UnlockCommercialFeatures -XX:+FlightRecorder`. 2017년 9월 Oracle 이 6개월 주기와 **오픈소스화 예고**(로드맵 미정). HotSpot 은 JFR 이식을 위해 SA 와 비슷한 카운터를 대량 계측했다.
7. **운영 도구**: **Red Hat Thermostat**(오픈소스, MongoDB, 플러그인) · **New Relic**(SaaS, 범용 → JVM 심층은 약하고 데이터가 너무 많다) · **jClarity Illuminate**(SLA 위반 시 딥다이브 프로브, Kirk Pepperdine 의 PDM 기반 ML — "데이터의 벽" 대신 근본 원인 보고서).
8. **현대적 프로파일러(세이프포인트 편향 없음)**: **Honest Profiler**(Richard Warburton; Jeremy Manson 의 Google 원형; **`AsyncGetCallTrace`** 사설 API + `SIGPROF` → 스레드 개별 인터럽트, 전역 동기화 없음, 락프리 링 버퍼; 인트린직 때문에 "Unknown" 이 뜬다; 바이너리는 직접 빌드) · **perf**(리눅스 커널, 하드웨어 카운터; JIT 코드 심볼은 **perf-map-agent**; **`-XX:+PreserveFramePointer`**(8u60, 최대 3% 비용) → **플레임 그래프**(Netflix)) · **Async Profiler**(같은 API, HotSpot 전용, perf 의존이라 리눅스).
9. **할당 프로파일링**: ① `jmap` 식 힙 방문(VisualVM·YourKit 메모리 뷰) ② **바이트코드 계측 에이전트** — 할당 opcode 는 **`NEW`·`NEWARRAY`·`ANEWARRAY` 셋뿐**. ASM 으로 `premain()` → `ClassFileTransformer` → `MethodVisitor` 가 각 opcode 앞에 `RuntimeCostAccounter.recordAllocation/recordArrayAllocation` 호출을 삽입(스레드별 `ThreadLocal<Long>` 누적). 단위·회귀 테스트에서 "할당이 늘지 않았나" 확인용으로는 좋지만 **운영엔 부적합**(호출이 너무 많다). ③ **TLAB 샘플링**(Async Profiler, 7u40+ 콜백 — 새 TLAB 할당 시·TLAB 밖 슬로패스 시만 기록 → n KB 마다 한 번) — 운영 가능하나 샘플이라 불완전.
10. **힙 덤프 분석**: 라이브 셋·타입별 수·객체 그래프 모양. 단점은 **크기**(힙의 300~400%) — 디스크·네트워크·워크스테이션 메모리, 그리고 **STW**. YourKit 은 hprof + 자체 형식, 클래스로더/웹앱별 분해. JMC 의 Allocations 뷰(TLAB 뷰).
11. **hprof**: JDK 5 부터 동봉됐지만 **JVMTI 참조 구현**일 뿐 운영 도구가 아니다. **Java 9(JEP 240) 에서 제거.** 힙 스냅샷 **형식**으로서의 hprof 는 남는다.

## 2. 절별 상세 요약

- **Introduction to Profiling** — 에이전트, 세 도구 부류, Knuth, 전제 조건 두 가지(CPU 100% 유저, GC 로그 조용).
- **Sampling and Safepointing Bias** — 100ms 샘플링, `GetCallTrace()` 비용, `PrintGCApplicationStoppedTime`, 카운티드 루프 예.
- **Execution Profiling Tools for Developers** — VisualVM(그림 13-1), JProfiler(13-2~13-7), YourKit(13-8), JFR/JMC(13-9~13-12).
- **Operational Tools** — Thermostat(13-13), New Relic(13-14), Illuminate(13-15).
- **Modern Profilers** — Honest Profiler(에이전트 옵션 `interval`·`logPath`, 그림 13-16), perf·perf-map-agent·`PreserveFramePointer`, 플레임 그래프(13-17), Async Profiler.
- **Allocation Profiling** — VisualVM·YourKit 메모리 뷰, ASM 에이전트 코드 전문(`AllocAgent`·`AllocRewriter`·`AllocationRecordingMethodVisitor`·`RuntimeCostAccounter`), TLAB 샘플링.
- **Heap Dump Analysis / hprof** — 크기·STW, YourKit(13-20), JMC Allocations(13-21), JEP 240 인용.

## 4. JDK 17 / 25 기준 보정 — Censum·hprof·상용 JFR 을 현재 도구로

| 책의 문장 | 지금 | 상태 |
|---|---|---|
| JFR 은 상용, `UnlockCommercialFeatures` 필요 | **JDK 11 부터 오픈소스**(JEP 328). `jfr` 도구가 17·21·25 에 있고 플래그 없이 `-XX:StartFlightRecording` 또는 `jcmd JFR.start`. `UnlockCommercialFeatures` 는 제거됐다 | ✅ 도구 목록 |
| JFR 은 `AsyncGetCallTrace` 를 쓴다(세이프포인트 편향 없음) | JFR 의 실행 샘플러는 자체 구현이나 같은 원리. **JDK 25 는 `jdk.CPUTimeSample`**(CPU 시간 기반 샘플러, JEP 509 실험) **·`jdk.MethodTrace`·`jdk.MethodTiming`(JEP 520) 이벤트가 추가**됐다 — 17·21 에는 없다 | ✅ CN-12A(이벤트 목록 비교) |
| `-XX:+PrintGCApplicationStoppedTime` 으로 세이프포인트 시간 | **JDK 17 에서 Unrecognized(기동 실패)**. 지금은 `-Xlog:safepoint` 또는 JFR `jdk.SafepointBegin/End` | ✅ CN-03A·`00-검토` §4 |
| `-XX:+PreserveFramePointer` 는 perf 용, 기본 꺼짐 | 그대로 — 17·21·25 모두 기본 `false`. `-XX:+DebugNonSafepoints`(진단, 기본 false)를 같이 켜야 인라인 프레임이 정확하다 | ✅ `PrintFlagsFinal` |
| perf 에 perf-map-agent 가 필요 | JDK 17 부터 **`-XX:+DumpPerfMapAtExit`** / `jcmd Compiler.perfmap` 으로 JDK 가 직접 `/tmp/perf-<pid>.map` 을 쓴다 | 📄 |
| Honest Profiler | 개발이 멈췄다. **Async Profiler** 가 사실상 표준(2판도 그렇다). IntelliJ 프로파일러도 그 위에 있다 | ✅ 키워드 / 📄 |
| Censum / Illuminate / Thermostat / New Relic | Censum·Illuminate 는 jClarity 인수(2019)로 종료 📄, Thermostat 종료 📄. New Relic 은 있으나 계측은 **OpenTelemetry 자바 에이전트**가 표준(2판 11장) | 📄 |
| hprof 에이전트 제거(Java 9) | 그대로. 힙 덤프는 `jcmd <pid> GC.heap_dump` / `jmap -dump` / JFR `jdk.OldObjectSample`. 형식은 여전히 hprof, 분석은 Eclipse MAT·JMC·VisualVM | ✅ `jmap`·`jcmd` 존재 |
| 할당 opcode 는 `NEW`·`NEWARRAY`·`ANEWARRAY` | `MULTIANEWARRAY` 도 배열을 만든다 — 책은 빠뜨렸다. 그리고 **C2 의 스칼라 치환은 바이트코드 계측이 잡지 못한다**(할당이 없어진다) — PERF-08A 의 프로브가 정확히 그렇게 GC 를 한 번밖에 못 냈다 | ✅ PERF-08A 첫 판 |
| TLAB 샘플링(7u40+) | JFR `jdk.ObjectAllocationInNewTLAB`·`jdk.ObjectAllocationOutsideTLAB` 가 표준 이벤트. JDK 16+ 는 `jdk.ObjectAllocationSample`(가중 샘플)로 더 싸졌다 | 📄 |
| 동적 에이전트 부착 | JDK 21 부터 **경고**(JEP 451) — `-XX:+EnableDynamicAgentLoading` 으로 잠재운다 | 📄 |

## 6. 면접에서 쓸 수 있는 문장

- "프로파일러를 붙이기 전에 두 가지를 확인합니다. CPU 가 유저 모드로 100% 에 가깝나, GC 로그는 조용한가. 아니면 프로파일러는 엉뚱한 곳을 가리킵니다."
- "옛 프로파일러는 세이프포인트에서만 샘플을 떠서 언롤된 작은 루프는 아예 안 보입니다. 그래서 JFR 이나 Async Profiler 처럼 세이프포인트 편향이 없는 도구를 씁니다. JDK 25 는 CPU 시간 샘플러 이벤트가 JFR 에 들어왔습니다."
- "바이트코드 계측 할당 프로파일러는 JIT 가 없앤 할당을 못 봅니다. 운영에서는 JFR 의 TLAB 샘플 이벤트가 싸고 충분합니다."
