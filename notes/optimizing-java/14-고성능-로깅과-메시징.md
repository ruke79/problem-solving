# 14장 — 고성능 로깅과 메시징 (High-Performance Logging and Messaging)

> *Optimizing Java* 1판(2018) 14장 요약. [`00-검토-2018년-책과-현재.md`](00-검토-2018년-책과-현재.md) §7 의 **착수 순서 4순위**(11·12장 뒤 — 12·14장 동시성). 표기 — ✅ 실행해 확인 · 📄 문서로만 아는 것.
>
> **2판(2024)에서는 이 장이 통째로 빠졌다.** 2판 14장은 「분산 시스템 기법과 패턴」(Kafka 62회)이고 Aeron·Agrona·SBE·Disruptor 언급은 **0회**다 ✅. 저지연 메시징 라이브러리 대신 클라우드의 브로커·백프레셔·회로 차단기로 관심이 옮겨 갔다. 그래서 이 요약은 **1판 고유 내용**이면서, 2판이 왜 뺐는지를 함께 적는다.

---

## 1. 이 장의 핵심 주장

1. **"자바는 고성능 시스템에 부적합한가?"** — 관리되는 추상화(GC)가 비결정성을 주지만, 저지연 시스템의 핵심인 **로깅과 메시징**에서 자바로 어디까지 가는지가 이 장의 답이다.
2. **로거 선정의 안티패턴**: **10년 로거**(누군가 한 번 설정한 것을 빌려 쓴다) · **프로젝트 로거**(로거를 감싼 래퍼) · **회사 로거**. 로깅은 비즈니스 크리티컬로 안 보여 방치되고 기술 부채가 조직 전체로 번진다. 로거를 **비용이 아니라 시스템의 구성 요소**로 다뤄라 — 정확한 처리와 감사 보고는 속도만큼 중요하다.
3. **로깅 마이크로벤치마크**(Stephen Connolly 의 JMH 스위트; Logback 1.2.1 · Log4j 2.7 · JUL; 포맷 세 종류; 대조군 "No logging"): iMac 에서 **JUL 42,404~86,054 ns/op**, Log4j 5,323~32,755, **Logback 3,501~27,420**(Log4j 포맷일 때 최고). AWS t2.2xlarge 도 같은 패턴(Logback 4,786 vs Log4j 5,835). 결론 — **JUL 이 가장 느리고, Log4j 포맷이 가장 일관되며, Logback 이 가장 빠르다.** 단 이것은 **"의미 있는 코퍼스가 없을 때"의 마이크로벤치마크 용법**이고, **운영 장비에서 전후 프로파일링**으로 확인해야 한다(수십 % 차이는 증거가 아니다). 마이크로벤치마크가 못 보는 것 — 로거가 만드는 **가비지**, 비즈니스 스레드에서 뺏는 CPU.
4. **저영향 로거 설계**: Kirk Pepperdine — "4.5초 예산 중 로깅이 4.2초인 고객". **Log4j 2.6 의 정상 상태 가비지 프리 로거**: JFR 로 12초 측정 — 2.5 는 GC 141회(평균 7 ms, 최대 52 ms), 2.6 은 **0회**. 방법은 **객체 풀 패턴**(ThreadLocal·버퍼 재사용, varargs 임시 배열 제거). 대가 — 웹 컨테이너에서는 ThreadLocal 을 안 쓴다(언로드 문제), **SLF4J 파사드는 파라미터 2개까지만** 가비지 프리(그 이상은 Log4j2 API 직접 사용). "마이크로벤치마크만 보고는 추론할 수 없는 결과".
5. **Real Logic 라이브러리**(Martin Thompson, 기계적 공감, Disruptor 의 창시자): **Agrona**(자료구조) · **SBE**(코덱) · **Aeron**(전송) · Artio(FIX 게이트웨이).
   - **Agrona 버퍼**: `ByteBuffer` 는 범용이라 원자 연산이 없고 감쌀 때마다 새 버퍼를 만든다. Agrona 는 `DirectBuffer`(읽기) → `MutableDirectBuffer`(쓰기) → `AtomicBuffer`(순서 보장) → **`UnsafeBuffer`**(Unsafe 구현). "짝수 주소일 때 `memset()` 을 유도하려는 끔찍한 필스(filth)" 주석 — 옛 JVM 최적화가 역최적화가 된 것을 우회. 바운드 검사는 켜고 끌 수 있어 JIT 가 죽은 코드를 지운다.
   - **원시 타입 컬렉션**: int/long 배열 기반 리스트, 키·값을 나란히 두는 오픈 어드레싱 맵/셋(같은 캐시 라인).
   - **큐**: `java.util.Queue` + `Pipe`(count·capacity·drain). 락 없음, Unsafe. **패딩 클래스 계층**(`p1..p15` / producer / `p16..p30` / consumer / `p31..p45`) 으로 생산자·소비자 필드를 **다른 캐시 라인**에 — 자바가 필드 배치를 보장하지 않기 때문. `OneToOne`(조정 최소) · `ManyToOne`(tail 을 CAS 루프) · `ManyToMany`(head·tail 모두 CAS) — **필요한 만큼만 조정**. `@Contended` 가 언젠가 이 패딩을 대신할 수 있다는 노트.
   - **링 버퍼**: `RecordDescriptor`(길이·타입·메시지), `OneToOneRingBuffer`·`ManyToOneRingBuffer`, 다중 생산자는 `Unsafe.storeFence()` 로 수동 동기화. JCTools 도 대안 — **바퀴를 다시 만들지 말라.**
   - **SBE**: FIX 용 바이너리 인코딩(FAST 의 후속, Protobuf·ASN.1 제안과 경쟁). 원칙 — **복사 없음**(중간 버퍼 없이 직접 쓰기; 버퍼보다 큰 메시지는 미지원) · **네이티브 타입 매핑** · **정상 상태 무할당**(플라이웨이트) · **스트리밍·워드 정렬 접근**(순서대로 읽어야 한다). XML 스키마 → `sbe-tool` 이 인코더/디코더 생성. "2분 GC 일시정지 버그" 목격담 — 일관된 속도가 요구사항.
   - **Aeron**: UDP 유니캐스트·멀티캐스트·IPC 전송(미디어 무관, InfiniBand 도). 구성 — **미디어 드라이버**(별도 프로세스 또는 임베디드 `MediaDriver.launch()`) · **컨덕터**(관리, NAK 재전송) · **센더** · **리시버**. `Publication.offer()` 결과 상수, `Subscription` + `FragmentHandler`. **OSI 4계층 책임** — 순서·신뢰성(연결 수준)·**백프레셔**·혼잡(옵션)·다중화. **여덟 설계 원칙** — 정상 상태 가비지 프리 · 스마트 배칭 · 락프리 · 논블로킹 I/O · 메시지 경로에 예외 경우 없음 · **단일 작성자 원칙** · 비공유 상태 · 불필요한 복사 회피. 구현 — **복제된 영속 로그**: 메모리 매핑 파일(기본 tmpfs), tail 원자 증가로 공간 예약 → 메시지 → **헤더를 마지막에** 써서 완료 표시, **active/dirty/clean 세 파일 회전**(메시지는 파일을 넘지 않는다), 순서가 어긋나면 빈칸을 두고 NAK 로 채운다, 워터마크, `streamId/sessionId/termId/termOffset` 으로 모든 메시지가 유일 → Aeron Archive 로 기록·재생.

## 2. 절별 상세 요약

- **Logging** — 안티패턴 셋, "정확하고 빠르게".
- **Logging Microbenchmarks** — 포맷 예시 세 줄, 표 14-1(iMac)·14-2(AWS), 결과 해석과 경고.
- **Designing a Lower-Impact Logger** — Pepperdine 인용, Log4j 2.5 vs 2.6 JFR 그림, ThreadLocal·varargs·SLF4J 제약.
- **Low Latency Using Real Logic Libraries** — Agrona(버퍼 계층 그림 14-3, Unsafe 코드, 패딩 클래스 전문, 링 버퍼 ASCII 레이아웃), SBE(설계 원칙 네 가지, `sbe-tool` 절차와 생성 파일 목록), Aeron(아키텍처 그림 14-4, API 예제, 전송 요구사항 다섯, 설계 원칙 여덟, 로그 파일 그림 14-5).

## 4. JDK 17 / 25 기준 평가

| 책의 문장 | 지금 | 상태 |
|---|---|---|
| Log4j 2.7 벤치마크 | **Log4j 2.0-beta9~2.14.1 은 Log4Shell(CVE-2021-44228, 2021-12)** — 책의 2.7 은 취약하다. 지금은 2.17 이상(2.24+)이 전제. 가비지 프리 모드는 유지 | 📄 |
| SLF4J 는 파라미터 2개까지 | **SLF4J 2.x 플루언트 API**(`atInfo().addArgument()`)로 varargs 배열 없이 인자를 더할 수 있다 | 📄 |
| JUL 이 가장 느리다 | 이 저장소에서 재측정하지 않았다. 로거 벤치마크는 §7 후보에 없었고 JMH 모듈(`verify-labs-jmh`)로 **잴 수는 있다** | 미검증 |
| Agrona 패딩, "`@Contended` 가 언젠가" | `@Contended` 는 `jdk.internal.vm.annotation` 에 있어 **`--add-exports` 가 필요**(17 ✅ `00-검토` §4). 그래서 라이브러리들은 여전히 **수동 패딩**을 쓴다 | ✅ |
| Agrona `UnsafeBuffer` 는 Unsafe 위 | **`sun.misc.Unsafe` 메모리 접근 메서드는 JDK 23 에서 제거 예정 폐기(JEP 471)**. JDK 25 에서 호출하면 **"A terminally deprecated method in sun.misc.Unsafe has been called"** 경고가 뜨고, `--sun-misc-unsafe-memory-access=deny` 면 `UnsupportedOperationException`. Agrona·Aeron 같은 라이브러리는 **FFM `MemorySegment`·`VarHandle` 로 옮겨야** 한다 | ✅ CN-15A |
| `Unsafe.storeFence()` | `VarHandle.storeStoreFence()`/`releaseFence()` 가 표준 대체(JDK 9) | 📄 |
| 커널 우회·네이티브 라이브러리 | JNI → **FFM API**(JDK 22 정식). 25 에서 `--enable-native-access` 없이 호출하면 경고 | ✅ CN-15B |
| Aeron 은 tail 원자 증가의 인트린직(Java 8) 에 의존 | `getAndAddLong` 인트린직은 그대로. Aeron·Agrona 는 활발히 유지되며 **JDK 17+ 를 요구**한다 | 📄 |
| "일관된 속도" — 2분 GC 일시정지 | 세대형 ZGC(21 옵션·24 기본)로 **일시정지 1 ms 미만**이 표준 옵션이 됐다 — 저지연 시스템이 GC 를 피해야 하는 이유가 약해졌다(할당 자체의 비용은 남는다) | ✅ CN-05A |

## 6. 면접에서 쓸 수 있는 문장

- "로깅은 비용이 아니라 구성 요소입니다. 로그 문장 하나의 ns/op 보다 로거가 만드는 가비지와 GC 가 서비스 스레드에 주는 영향이 큽니다. 그래서 Log4j2 의 가비지 프리 모드 같은 설계를 봅니다."
- "저지연 큐가 `p1..p15` 같은 패딩 필드를 두는 이유는 생산자와 소비자 필드를 다른 캐시 라인에 두기 위해서입니다. 자바는 필드 배치를 보장하지 않고 `@Contended` 는 내부 API 라서요."
- "Unsafe 위에 만든 라이브러리는 JDK 25 에서 경고가 뜨고 곧 막힙니다. FFM 의 `MemorySegment` 와 `VarHandle` 이 대체 경로입니다."
